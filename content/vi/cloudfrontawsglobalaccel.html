Amazon CloudFront: CDN & origins

Mục đích: Phân phối web/file qua edge gần người dùng để giảm latency và tải lên backend.

1. Cache ở edge

Viewer → edge location
          ├─ cache hit → trả nội dung
          └─ cache miss → origin → cache khi policy cho phép → trả nội dung

Origin: nơi có nội dung gốc.

Distribution có một hoặc nhiều origins; cache behavior quyết định origin và policy cho từng URL path.

CloudFront phân phối cả static và dynamic HTTP(S), không chỉ file tĩnh. Request không cache vẫn có thể dùng đường mạng và connection optimization.

CloudFront và origin không cần cùng AZ. CloudFront là dịch vụ toàn cầu chạy ở edge locations; origin có thể nằm trong AWS Region hoặc on-premises. VPC origin phải dùng Region và tài nguyên được hỗ trợ.

2. Các origin

Origin / cơ chếChức năngVí dụ
S3 OriginLấy nội dung từ S3 bucketHTML, CSS, JS, ảnh
Custom OriginLấy nội dung từ HTTP/HTTPS serverPublic ALB, EC2, web server on-premises
VPC OriginKết nối riêng tới tài nguyên VPC được hỗ trợInternal ALB, NLB, EC2
Origin GroupNhóm primary + secondary origins để failoverPrimary ALB lỗi → secondary S3 phục vụ trang dự phòng

Origin Group là nhóm dự phòng, không phải một loại server. Failover theo lỗi kết nối/status codes đã cấu hình, chỉ cho GET/HEAD/OPTIONS; OPTIONS còn phải được bật trong cached HTTP methods. Không dùng cơ chế này để tự failover POST.

VPC origin giúp origin private, nhưng vẫn phải đáp ứng các yêu cầu SG/network và tính năng được hỗ trợ.

Public custom origin cần hạn chế việc người dùng bỏ qua CloudFront nếu yêu cầu bảo vệ ở edge.

3. Cache Behaviors chọn origin

Path patternOriginRequest ví dụ
/images/*S3/images/logo.png
/api/*ALB/api/orders
Default (*)On-premises server/home

CloudFront xét behaviors theo thứ tự đã cấu hình và dùng behavior khớp đầu tiên; không tự chọn pattern cụ thể nhất. Nếu không khớp behavior riêng, dùng Default Cache Behavior (*).

4. Private S3 và OAC

OAC ký request từ CloudFront, bucket policy cho distribution được đọc; không cần mở public bucket. Object SSE-KMS còn cần KMS key policy phù hợp.

S3 REST bucket origin khác S3 website endpoint. Website endpoint là custom HTTP origin, không dùng OAC theo cách private bucket origin.

5. TLS và bảo vệ edge

Custom domain cần certificate đúng tên.

ACM certificate cho viewer → CloudFront phải ở us-east-1; certificate cho origin là chặng riêng. AWS CloudFront certificate requirements.

WAF lọc request ứng dụng; Shield giúp bảo vệ DDoS; signed URL/cookie kiểm soát viewer truy cập private content.

OAC cấp quyền CloudFront đọc S3, không tự xác thực từng user.

6. Use cases

Use cases: Website/ảnh/video toàn cầu: CloudFront + S3. App private cần edge delivery: VPC origin phù hợp. API HTTP(S): behavior/cache policy theo nội dung và security requirements.

7. CloudFront Video Streaming (VOD vs Live) & Custom Domain HTTPS

Kiểu StreamingKiến trúc chuẩn trên AWSCơ chế cache trên CloudFront
Video On-Demand (VOD)S3 (Origin) → CloudFront → UsersCache trực tiếp các file/segments video tĩnh đã lưu sẵn trên S3
Live StreamingCamera → Elemental MediaLive (encode) → MediaPackage (segments/playlist) → CloudFrontCloudFront không encode nhưng cache ngay từng segment đã tạo xong (manifest giữ TTL ngắn)
Custom Domain HTTPS trên CloudFront:
1. Xin Public Certificate trong ACM tại Region us-east-1
2. Khai báo Alternate Domain Name (CNAME) trên CloudFront + gắn chứng chỉ ACM

Nhớ nhanh · SAA-C03

CloudFront là CDN cache gần người dùng, phân phối từ origins. S3 origin và custom origin có chính sách bảo vệ origin khác nhau.

CloudFront caching, delivery controls & geo restriction

Mục đích: Cache đúng nội dung, cập nhật đúng lúc và giới hạn người được nhận nội dung.

Luồng cache:

Viewer request
↓ Cache key
CloudFront edge
├─ hit → cached response
└─ miss → origin → response / cache theo policy

1. Cache key

Cache key xác định request nào dùng chung response. Path là phần chính; có thể thêm query strings, headers/cookies làm nội dung khác nhau.

Đưa quá nhiều biến vào key làm giảm cache hit.

Bỏ biến thật sự thay đổi nội dung có thể trả nhầm dữ liệu; response riêng theo user cần policy an toàn hoặc không cache.

2. Cache policy và origin request policy

Cache policy quyết định key/TTL. Origin request policy chuyển thêm thông tin xuống origin dù không nằm trong key.

Forward header/cookie không tự đảm bảo response riêng biệt. Kiểm tra cache behavior cùng Cache-Control của origin, đặc biệt minimum TTL và dữ liệu nhạy cảm.

3. TTL, file version và invalidation

TTL quy định thời gian cache.
Origin đổi file không tự làm mọi edge lấy bản mới ngay.
Dùng tên version như app.abc123.js cho asset lâu đổi; HTML có thể TTL ngắn
hơn.

Invalidation loại path khỏi cache trước TTL: /index.html, /images/* hoặc /*.

Wildcard path giúp xóa nhiều object nhưng invalidation vẫn có quota/chi phí; không phải cơ chế backup hay sửa file gốc.

4. Signed URL và signed cookie

Signed URL hợp một file cụ thể; signed cookie hợp nhiều file như video có
nhiều segment.
Cả hai kiểm soát thời hạn/điều kiện truy cập private content qua CloudFront.

Chặn truy cập trực tiếp origin nếu muốn mọi user phải qua kiểm tra này. S3 pre-signed URL là cơ chế khác, cấp request trực tiếp tới S3 bằng quyền signer.

5. Geo restriction

Allowlist/blocklist theo quốc gia ở distribution dựa vào Geo-IP.
VPN/proxy có thể ảnh hưởng vị trí nhận diện; không thay
authentication/authorization theo user.

6. Price Class

Price Class chọn nhóm edge locations phục vụ distribution để cân bằng chi phí và latency.

Price ClassPhạm viMục tiêu
100Mỹ, Canada, châu Âu, IsraelGiới hạn ở các khu vực có chi phí thấp hơn
200Class 100 + nhiều khu vực châu Á, châu Phi, Trung Đông; có Việt NamCân bằng chi phí và độ phủ
AllTất cả CloudFront edge locationsĐộ phủ toàn cầu lớn nhất

Ví dụ khách hàng ở Việt Nam: Class 100 không bao gồm edge ở Việt Nam nên có thể phải đi xa hơn; Class 200 bao gồm Việt Nam nên có thể giảm latency; All mở toàn bộ mạng edge. Chi phí thực tế phụ thuộc traffic và khu vực phục vụ.

Price Class không chặn người dùng theo vị trí. Người ở ngoài phạm vi vẫn truy cập được; muốn giới hạn quốc gia thì dùng Geo Restriction/WAF.

7. Viewer Protocol Policy

PolicyÝ nghĩa
HTTP and HTTPSCho phép cả hai giao thức
Redirect HTTP to HTTPSChuyển viewer HTTP sang HTTPS; request HTTP/1.0 dùng các method ghi có thể bị từ chối
HTTPS OnlyChỉ cho HTTPS; HTTP bị trả 403

Policy áp dụng cho chặng viewer → CloudFront; chặng CloudFront → origin có protocol policy riêng.

8. Use cases

Use cases: JS/CSS versioned: TTL dài. HTML đổi gấp: invalidation. Nội dung trả phí một file: signed URL; nhiều video segments: signed cookie. Nội dung khác nhau theo query: cache key chứa query cần thiết.

9. Automatic Compression (Gzip/Brotli) & 4 Điểm móc Viewer/Origin Events

Automatic Compression: khi trình duyệt gửi Accept-Encoding: br, gzip, CloudFront tự nén các file đủ điều kiện bằng Brotli/Gzip tại Edge, cache bản nén và trả kèm Content-Encoding.

AWS Global Accelerator

Mục đích: Đưa traffic TCP/UDP vào mạng AWS gần client, giữ IP ổn định và chuyển tới endpoint khỏe.

1. Anycast và đường mạng

Anycast
= nhiều điểm mạng quảng bá cùng IP; client đi tới edge phù hợp rồi traffic
theo AWS backbone tới endpoint.
Client → static Anycast IP → AWS edge → AWS backbone → regional endpoint

Global Accelerator IPv4 thường cung cấp hai static IPv4; dual-stack có thêm IPv6. IP giữ ổn định khi đổi backend, hữu ích cho firewall allowlist.

2. Endpoint và health

Endpoint group theo Region chứa ALB, NLB, EC2 hoặc EIP theo cấu hình hỗ trợ.
Health kiểm soát nơi nhận traffic; endpoint weight và traffic dial điều chỉnh
phân phối.
Traffic dial đổi tỷ lệ traffic vào một Region; endpoint weight chia trong
group.
Khi lỗi, service đổi network routing mà không phải đợi client hết DNS cache để
nhận một IP mới.

3. Không có cache

Global Accelerator tăng tốc đường mạng, không cache HTTP object.
Nội dung mới vẫn tới ứng dụng; TLS, authentication và kiểm soát request vẫn
cần ở endpoint/ứng dụng.

Không nhầm static IP của Global Accelerator với static IP theo AZ của một NLB: Accelerator đưa traffic toàn cầu tới regional endpoints.

4. Use cases

Use cases: Game UDP, VoIP, app TCP toàn cầu; API nhiều Region cần IP allowlist ổn định và nhanh chuyển khỏi endpoint lỗi. Website cần cache ảnh/video gần user: cân nhắc CloudFront.

5. Các loại Endpoint đích được Global Accelerator hỗ trợ

Global Accelerator định tuyến được tới cả Internet-facing ALB/NLB, Internal ALB/NLB, EC2 Instances và Elastic IP trong một hoặc nhiều Region mà không để lộ cấu trúc mạng nội bộ.

Nhớ nhanh · SAA-C03

Global Accelerator dùng static anycast IP và mạng AWS toàn cầu để cải thiện đường tới regional endpoints; không cache nội dung như CloudFront.

CloudFront vs Global Accelerator vs S3 CRR

Mục đích: Phân biệt tăng tốc nội dung, tăng tốc mạng và sao chép dữ liệu bền vững.

Ba cơ chế:

CloudFront = HTTP(S) delivery + cache
Global Accelerator = TCP/UDP acceleration, không cache
S3 CRR = copy object sang Region khác

1. Bảng so sánh

Cơ chếLàm gì?Khi chọn
CloudFrontCDN cho HTTP(S), cache tại edge và đưa request tới originWeb/API, ảnh, video, signed content
Global AcceleratorTCP/UDP qua AWS backbone với static Anycast IP, không cacheApp toàn cầu, IP allowlist, network failover
S3 CRRReplicate object sang bucket ở Region khác, bất đồng bộDR, compliance, dữ liệu phải có bản sao regional

2. Cache khác replica

CloudFront cache có thể bị evict hoặc hết TTL; origin vẫn là nguồn dữ liệu.

CRR tạo object thật ở bucket đích, cần Versioning và permission; app muốn đọc bản đích phải truy cập đúng bucket/endpoint.

Không dùng CloudFront cache thay backup/DR cho S3. CRR không tự phân phối HTTP tới edge hoặc tự chuyển mọi client sang bucket dự phòng.

3. CloudFront khác Accelerator

CloudFront hiểu HTTP và có cache behavior, signed URL/cookie, geo restriction.
Global Accelerator xử lý đường TCP/UDP và static IP; không có cache key/TTL
như CDN.

HTTP app cũng có thể dùng Accelerator khi cần IP cố định/failover mạng. Chọn theo yêu cầu chính, không chỉ dựa vào từ “global”.

4. Use cases

Use cases: Website ảnh: CloudFront. Game UDP nhiều Region: Global Accelerator. Object cần bản sao Region khác: CRR. Có thể CRR cho DR và CloudFront cho delivery, nhưng vẫn phải cấu hình origin/failover phù hợp.

Nhớ nhanh · SAA-C03

CloudFront tối ưu HTTP content caching; Global Accelerator tối ưu network path/TCP-UDP; S3 CRR sao chép dữ liệu giữa Regions.
