Amazon S3 fundamentals, buckets & websites

Mục đích: Amazon S3 là dịch vụ object storage để lưu file, backup, log, data lake và static content với độ bền và khả năng mở rộng rất cao.

S3 = Object Storage = File / Backup / Log / Data Lake

1. Bucket & Object

S3 lưu dữ liệu theo:

Bucket
↓
Object

Object gồm: Key · Value (data/file) · Metadata

Ví dụ:

Bucket: company-data · images/logo.png · logs/2026/app.log · reports/report.pdf

images/ hay logs/ chỉ là prefix logic, không phải folder filesystem thật.

Bucket = container, Object = file/data, Key = tên/path của object.

2. Bucket & Region

Bucket được tạo trong một AWS Region.

S3 Bucket
↓
ap-southeast-1

Bucket name theo namespace S3 thông thường phải unique.

Một số rule quan trọng: 3–63 ký tự · lowercase · không underscore _ · không giống IP address

S3 nhìn như global service, nhưng data của bucket nằm trong Region đã chọn.

S3 encryption, HTTPS & CORS

Mục đích: Bảo vệ nội dung lưu trong S3, mã hóa đường truyền và cho browser truy cập đúng origin.

1. Encryption at rest

CáchAi quản key?Điểm cần hiểu
SSE-S3S3/AWSMã hóa server-side AES-256; mặc định cho object mới
SSE-KMSAWS KMSKiểm soát key policy, audit key usage, có KMS permission/quota/cost
SSE-CKhách hàngGửi key mỗi request qua HTTPS; S3 không lưu key để dùng lần sau
Client-sideỨng dụng/khách hàngMã hóa trước upload; S3 chỉ nhận ciphertext

Mã hóa không tự cấp quyền truy cập và không thay bucket policy. Đổi default encryption không tự mã hóa lại mọi object cũ theo loại/key mới.

2. SSE-KMS

Upload cần quyền phù hợp như kms:GenerateDataKey; đọc cần kms:Decrypt.
Truy cập cross-account phải có S3 permission và customer managed KMS key cho
phép phía kia.

Request rate của KMS có thể trở thành giới hạn khi S3 traffic lớn.

S3 Bucket Keys giúp giảm số request KMS và chi phí cho SSE-KMS khi phù hợp; vẫn phải giữ đúng key policy.

3. HTTPS

TLS/HTTPS bảo vệ khi truyền. Bucket policy có thể explicit Deny nếu aws:SecureTransport=false để từ chối HTTP.

Client --HTTPS--> S3 --server-side encryption--> object được lưu
S3 website endpoint không hỗ trợ HTTPS trực tiếp; dùng CloudFront cho website
HTTPS.
SSE-C bắt buộc HTTPS và phải giữ key an toàn, mất key thì không giải mã được.

4. CORS

Origin gồm protocol, host và port. Web ở https://app.example.com gọi S3 ở origin khác cần CORS trên bucket đích với origin/method/header phù hợp.

CORS là quy tắc browser cho đọc response, không cấp quyền S3 và không ngăn mọi client ngoài browser. Pre-signed URL/bucket policy vẫn phải cho phép action trước.

5. Use cases

Use cases: Cần kiểm soát/audit key: SSE-KMS. Browser upload thẳng S3: pre-signed PUT + CORS. Dữ liệu phải mã hóa trước khi tới S3: client-side. Chỉ cho đường truyền bảo mật: policy ép HTTPS.

Nhớ nhanh · SAA-C03

SSE-S3/SSE-KMS/SSE-C là mã hóa phía server; HTTPS bảo vệ in transit; CORS là cơ chế trình duyệt, không phải IAM permission.

S3 versioning, replication & immutable protection

Mục đích: Khôi phục object bị ghi đè/xóa nhầm, có bản sao ở nơi khác và giữ dữ liệu không bị phá hủy trước hạn.

Ba cơ chế khác nhau:

Versioning = giữ các version
Replication = copy sang bucket khác
Object Lock = bảo vệ version theo retention

1. Versioning

Bật ở bucket để giữ nhiều version của cùng key. Ghi đè tạo version mới; DELETE thông thường thêm delete marker, không xóa ngay các version cũ.

Khôi phục bằng cách lấy version cũ hoặc xóa delete marker phù hợp. Xóa kèm version ID có thể xóa vĩnh viễn version đó. Suspend Versioning không tự xóa các version đã có.

2. CRR và SRR

CRR replicate sang Region khác; SRR replicate trong cùng Region.

Có thể cross-account, cần Versioning ở source/destination cùng role và policy phù hợp; object SSE-KMS còn cần cấu hình/quyền KMS.

Replication bất đồng bộ: không hứa dữ liệu xuất hiện tức thời.
Mặc định rule live replication áp dụng object mới sau khi bật; object cũ dùng
S3 Batch Replication.

3. Xóa và replication

Delete marker có thể replicate nếu bật tùy chọn và rule phù hợp. Xóa vĩnh viễn một version ở source không tự replicate việc xóa đó sang destination.

Không có chaining tự động: object replicate A → B không tiếp tục tự đi B → C
chỉ vì B có rule tới C.
Muốn nhiều đích, cấu hình replication thích hợp từ nguồn.

4. MFA Delete

Yêu cầu MFA khi xóa vĩnh viễn version hoặc thay đổi trạng thái Versioning. Không yêu cầu MFA chỉ để thêm delete marker thông thường.

Bucket owner/root bật hoặc tắt MFA Delete qua API/CLI với MFA, không qua S3 Console. Versioning phải được bật.

5. Object Lock

WORM bảo vệ từng version; cần Versioning.

Có thể bật cho bucket mới hoặc bucket hiện hữu theo quy trình hỗ trợ; đã bật thì không tắt Object Lock/Versioning theo cách thông thường.

Cơ chếÝ nghĩa
Governance retentionNgười có quyền bypass phù hợp có thể vượt bảo vệ
Compliance retentionKhông ai, kể cả root, xóa/rút ngắn retention của version đang khóa
Legal holdGiữ tới khi người có quyền gỡ hold; độc lập với retention date
Lock version hiện có vẫn cho phép ghi một version mới cùng key.
Legal hold không tự hết hạn; retention hết hạn chưa chắc xóa được nếu legal
hold còn bật.

6. Use cases

Use cases: File bị overwrite: Versioning. DR/compliance nhiều Region: CRR. Backup chống ransomware hoặc hồ sơ cần giữ nguyên: Object Lock, quyền giới hạn và policy retention phù hợp.

Nhớ nhanh · SAA-C03

Versioning giữ nhiều phiên bản; Replication sao chép object giữa buckets; Object Lock bảo vệ phiên bản khỏi xóa/sửa theo retention.

S3 storage classes & lifecycle

Mục đích: Chọn storage class phù hợp để tối ưu chi phí dựa trên:

Tần suất truy cập · Retrieval time · Số AZ · Thời gian lưu · Khả năng tái tạo data

1. Tổng quan Storage Classes

  • S3 Standard = truy cập thường xuyên
  • Standard-IA = ít truy cập = multi-AZ
  • One Zone-IA = ít truy cập = 1 AZ
  • Intelligent-Tiering = AWS tự đổi tier theo access pattern
  • Glacier = archive / long-term storage
  • Express One Zone = 1 AZ = latency rất thấp / performance cao
  • Điểm chung: Durability = 99.999999999% (11 số 9)

Điểm khác nhau chủ yếu: Availability · AZ · Storage cost · Retrieval cost · Retrieval time · Minimum storage duration

2. S3 Standard

S3 Standard = general purpose = frequent access = multi-AZ = low latency = high throughput

Không có: Retrieval fee · Minimum storage duration

Phù hợp: Active application data · Web content · Big Data · Mobile / Gaming

Theo slide: Minimum storage duration = 30 ngày

Use cases:

Backups · Disaster Recovery · Data ít truy cập

Ví dụ:

Thumbnails · Secondary backup · Re-creatable data

Điểm thi: cần infrequent access + data có thể recreate → nghĩ tới One Zone-IA.

5. S3 Intelligent-Tiering

Dùng khi: Không biết trước · access pattern

AWS tự theo dõi access và chuyển object giữa các tier.

Frequent Access

Infrequent Access

Ưu điểm: Tự động tối ưu storage cost · Không cần tự viết transition theo access pattern · Không có retrieval fee giữa các access tier

Có: Monitoring / automation fee

Điểm thi: access pattern không ổn định hoặc không dự đoán được → Intelligent-Tiering.

6. S3 Glacier Classes

Dùng cho: Archive · Backup · Long-term retention

6.1. Glacier Instant Retrieval

Retrieval = milliseconds

Archive ít truy cập · nhưng khi cần phải lấy ngay

Minimum storage = 90 ngày

6.2. Glacier Flexible Retrieval

Retrieval có thể chọn: Expedited = 1–5 phút

Standard = 3–5 giờ

Bulk = 5–12 giờ

Phù hợp archive khi: không cần lấy ngay lập tức

6.3. Glacier Deep Archive

Rẻ nhất + retrieval chậm nhất

Standard ≈ 12 giờ

Bulk ≈ 48 giờ

Minimum storage = 180 ngày

Compliance archive · Long-term backup · Data nhiều năm ít khi truy cập

S3 events & service integrations

Mục đích: Tự xử lý khi có object mới hoặc thay đổi, thay vì liên tục dò bucket.

1. Luồng event

Upload object → S3 event → SQS / SNS / Lambda / EventBridge
                           └─ processor đọc object từ bucket

Event mô tả bucket/key/version và thao tác, không chứa toàn bộ nội dung file. Có thể lọc prefix/suffix để chỉ xử lý uploads/ hoặc .jpg.

2. Chọn destination

SQS làm buffer cho worker; SNS fan-out; Lambda xử lý trực tiếp; EventBridge có rule/filter và nhiều loại target.

Đích trực tiếp SQS/SNS/Lambda phải cùng Region với bucket theo cấu hình hỗ trợ.

S3 không gửi trực tiếp vào SQS FIFO; dùng EventBridge nếu cần FIFO target. AWS notification destinations.

3. Permission nằm ở đâu?

Destination resource policy cho s3.amazonaws.com quyền sqs:SendMessage, sns:Publish hoặc lambda:InvokeFunction.

Giới hạn bằng source bucket ARN và source account; đích dùng KMS còn cần key permission phù hợp.

Role của consumer là lớp khác: worker/Lambda cần quyền đọc object và giải mã nếu cần. Policy cho S3 phát event không tự cấp quyền đọc file cho consumer.

4. Trùng event và vòng lặp

Event có thể giao hơn một lần và không đảm bảo thứ tự toàn cục. Consumer phải idempotent: cùng object/version xử lý lại không tạo tác dụng trùng không mong muốn.

Tách input/output prefix hoặc bucket. Lambda ghi thumbnail vào cùng prefix đang trigger có thể tự gọi lặp vô hạn.

5. Use cases

Use cases: Upload ảnh → thumbnail. File mới → SQS → worker xử lý có retry. Event theo loại object → EventBridge → Step Functions cho nhiều bước.

Nhớ nhanh · SAA-C03

S3 Event Notifications và EventBridge/SNS/SQS/Lambda cho luồng xử lý bất đồng bộ; cần hiểu khả năng retry và cách xử lý event trùng.

S3 performance, Requester Pays & Batch Operations

Mục đích: Tăng tốc truyền file, thao tác trên nhiều object và chọn bên trả chi phí đọc dữ liệu.

Các công cụ theo nhu cầu:

Multipart Upload = chia file thành nhiều part
Byte-range GET = đọc một phần object
Transfer Acceleration = tăng tốc truyền qua edge
Batch Operations = xử lý nhiều object
Requester Pays = requester trả phí request/data transfer

1. Request rate theo prefix

S3 hỗ trợ ít nhất 3.500 PUT/COPY/POST/DELETE và 5.500 GET/HEAD mỗi giây trên mỗi partitioned prefix.

Phân bố workload qua nhiều prefix giúp tăng tổng throughput; khi scale nhanh có thể gặp 503 Slow Down và cần retry/backoff.

Prefix: phần đầu của object key, không phải folder vật lý.

Với SSE-KMS còn phải xét KMS request quota.

2. Multipart Upload

Chia object thành các part upload song song; part lỗi chỉ cần gửi lại part đó.
Thường đáng dùng từ khoảng 100 MB, bắt buộc khi vượt giới hạn single PUT 5 GB.

Object tối đa hiện là 50 TB qua multipart, thay cho 5 TB trong tài liệu cũ.

Cấu hình lifecycle dọn incomplete multipart upload để tránh phí part bỏ dở. AWS object upload limits.

3. Transfer Acceleration và byte-range GET

Transfer Acceleration nhận dữ liệu ở edge location rồi dùng mạng AWS tới bucket, hợp upload từ nơi xa qua Internet; phải bật trên bucket và đo lợi ích so với chi phí.

Có thể kết hợp multipart.

Byte-range GET lấy một phần object hoặc nhiều range song song, hợp đọc header/file chunk và tăng tốc download; lỗi chỉ retry phần tương ứng.

4. Batch Operations

Một job gồm manifest object, action và IAM role.

Dùng để copy, đổi tag, restore archive hoặc invoke Lambda trên rất nhiều object; service theo dõi và tạo completion report.

Dùng Inventory/Athena để chọn object vào manifest khi phù hợp. Đổi encryption object cũ thường cần copy/rewrite, không chỉ đổi default encryption ở bucket.

5. Requester Pays

Requester được xác thực trả phí request và download; bucket owner vẫn trả storage. Requester phải xác nhận trả phí; anonymous access không hỗ trợ.

Đây là cơ chế tính phí, không cấp quyền đọc bucket. Vẫn cần policy cho phép request.

6. Use cases

Use cases: Video lớn: multipart. Upload từ nhiều châu lục: thử Transfer Acceleration. Retag hàng triệu object: Batch Operations. Chia dataset lớn cho account khác: Requester Pays.

S3 access control, sharing & access points

Mục đích: Cấp quyền tới đúng bucket/object và chia sẻ file private mà không mở public toàn bộ dữ liệu.

1. IAM policy, bucket policy và ACL

IAM policy cấp quyền cho user/role; bucket policy cấp quyền từ phía resource, hữu ích cho cross-account hoặc AWS service.

Explicit Deny vẫn thắng Allow; SSE-KMS thêm lớp quyền key.

Bucket ARN dùng cho action cấp bucket như ListBucket; object ARN dùng cho
GetObject/PutObject.
Không dùng nhầm arn:aws:s3:::bucket với arn:aws:s3:::bucket/*.

S3 ACL — quyền trên bucket hoặc object

S3 ACL (Access Control List) cấp quyền cơ bản cho AWS account hoặc nhóm được hỗ trợ trên bucket hoặc từng object; không có mức chi tiết/điều kiện như IAM và bucket policy.

LoạiPhạm vi và ví dụ
Bucket ACLQuyền ở cấp bucket: READ cho phép liệt kê objects; không tự cho phép đọc nội dung mọi object.
Object ACLQuyền trên từng object: READ để đọc file; READ_ACP/WRITE_ACP để đọc/sửa ACL.
READ = liệt kê bucket hoặc đọc object, tùy loại ACL
WRITE = tạo/xóa object ở cấp bucket; không áp dụng cho Object ACL
READ_ACP = đọc ACL
WRITE_ACP = sửa ACL
FULL_CONTROL = toàn bộ quyền ACL áp dụng cho tài nguyên đó

Ví dụ: Account A sở hữu report.pdf và cấp quyền đọc cho Account B qua Object ACL khi ACL đang bật.

AWS Account A
└── S3 Bucket
    ├── Bucket ACL → quyền cấp bucket
    └── report.pdf
        └── Object ACL → Account B: READ

ACL cấp cho account B qua canonical user ID; B cần cho phép IAM principal của mình dùng quyền được cấp. Explicit Deny và quyền KMS (nếu có) vẫn được kiểm tra.

Bucket mới mặc định dùng Object Ownership = Bucket owner enforced: ACL bị vô hiệu, quản lý quyền bằng policy. Thông thường giữ mặc định này và dùng bucket/IAM policy cho cross-account.

2. Pre-signed URL

Backend ký URL cho một action/key trong thời gian giới hạn.

Người có URL dùng quyền signer cho request đó, không cần nhận access key; URL là bearer token nên phải giữ kín.

URL không vượt quyền signer và có thể hết hạn sớm khi credential tạm thời hết hạn.

Với SigV4 và IAM User credential, thời hạn tối đa thường 7 ngày; không coi mọi URL đều sống được 7 ngày.

Pre-signed URL không mặc định chỉ dùng một lần. Upload browser cần CORS phù hợp ngoài quyền PutObject.

3. Access Points

Mỗi Access Point có hostname và policy riêng cho ứng dụng/team, cùng trỏ tới
một bucket.
Bucket policy và access point policy phải phối hợp; Access Point không bỏ qua
bucket guardrail.

VPC-only Access Point giới hạn truy cập qua VPC được chỉ định, kết hợp VPC Endpoint và endpoint policy.

Có route tới S3 vẫn cần đủ quyền IAM/bucket/access point/KMS.

Multi-Region Access Point (MRAP)

MRAP cung cấp một global endpoint cho các S3 buckets ở nhiều Regions. Request tự đi qua mạng AWS tới bucket có độ trễ mạng thấp nhất trong các bucket có active routing status; MRAP tự động tích hợp AWS Global Accelerator.

             Users toàn cầu
                   |
                   v
          MRAP Global Endpoint
                   |
           +-------+-------+
           |               |
           v               v
       S3 Bucket A     S3 Bucket B
       US Region       Singapore
           |               |
           +----- CRR -----+
             Sao chép dữ liệu

MRAP định tuyến request; CRR sao chép dữ liệu. Phải cấu hình Cross-Region Replication riêng giữa các buckets; nếu nhận ghi ở cả hai Regions, cấu hình replication hai chiều phù hợp. CRR bất đồng bộ, nên dữ liệu không xuất hiện tức thời ở bucket còn lại.

MRAP không chọn bucket dựa trên việc object có tồn tại hay không: GET có thể trả 404 nếu bucket được chọn chưa có object. Ví dụ: người dùng Mỹ và Singapore dùng cùng endpoint để đọc dữ liệu đã replicate ở hai Regions. ·

4. S3 Object Lambda

Object Lambda dùng Lambda biến đổi nội dung khi trả qua Object Lambda Access Point, ví dụ che PII hoặc đổi format; object gốc không bị sửa.
