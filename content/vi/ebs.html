Amazon EBS: persistent block storage

Mục đích: Cung cấp disk bền vững cho EC2, dùng cho hệ điều hành, filesystem và database.

Luồng sử dụng:

EC2
↓ attach block volume trong cùng AZ
EBS
↓
Filesystem / Database

1. Volume thuộc một AZ

EBS: block storage qua mạng.

Volume và EC2 phải cùng AZ; thường một volume gắn một instance, một instance có thể có nhiều volume.

Volume vẫn còn khi stop máy.

Khi terminate, DeleteOnTermination quyết định có xóa volume không; root thường bật, data volume thường tắt.

Kiểm tra thuộc tính thay vì mặc định rằng dữ liệu luôn còn.

2. Chọn loại volume

LoạiPhù hợp

Database random I/O khác với xử lý file lớn tuần tự.

4. gp3 và mở rộng volume

Baseline gp3: 3.000 IOPS và 125 MiB/s.

Có thể mua thêm performance mà không phải tăng disk chỉ để lấy IOPS.

Giới hạn gp3 hiện tại đã tăng so với slide cũ; xem AWS EBS gp3 khi cấu hình thực tế.

Elastic Volumes cho phép tăng dung lượng hoặc đổi performance/type khi máy đang chạy; có thể cần mở rộng partition/filesystem trong OS.

EBS tính phí theo capacity đã cấp, không chỉ số byte đang dùng.

5. Multi-Attach

io1/io2 hỗ trợ gắn cùng volume vào tối đa 16 Nitro instances trong cùng AZ khi cấu hình được hỗ trợ.

Các máy có thể đọc/ghi, nhưng ứng dụng phải có locking và filesystem cluster-aware để tránh hỏng dữ liệu.

Multi-Attach không biến EBS thành shared file system đa AZ. Nhiều Linux server dùng chung file thường hợp EFS hơn.

6. Use cases

Use cases: Boot disk/dev server: gp3. Database trên EC2 cần I/O nhất quán: io2. Log hoặc dữ liệu lớn tuần tự: st1. Muốn chuyển AZ: snapshot rồi tạo volume mới ở AZ đích.

EBS snapshots, AMI & encryption

Mục đích: Backup disk, tạo máy nhất quán và bảo vệ dữ liệu EBS bằng mã hóa.

1. Snapshot

Snapshot là bản sao tại một thời điểm.
Snapshot đầu sao chép block có dữ liệu; các lần sau lưu block thay đổi.
Xóa snapshot cũ không làm mất khả năng khôi phục từ snapshot còn lại.

Không bắt buộc tháo volume để snapshot. Muốn backup nhất quán với database, cần flush/quiesce ứng dụng hoặc quy trình backup phù hợp. Snapshot không chứa RAM.

Có thể tạo volume ở AZ khác từ snapshot.

Copy snapshot sang Region/account khác cần quyền chia sẻ và quyền KMS phù hợp; snapshot dùng AWS managed key không chia sẻ cross-account như customer managed key.

2. Các tính năng backup

Tính năngGiải quyết vấn đề
Snapshot ArchiveLưu backup hiếm dùng với chi phí thấp hơn; restore thường mất 24–72 giờ
Recycle BinKhôi phục snapshot/AMI xóa nhầm nếu có retention rule
Fast Snapshot RestoreVolume tạo từ snapshot có performance đầy đủ ngay, tránh first-read latency; có thêm phí theo AZ

EBS Snapshot Archive

EBS Snapshot Archive là lớp lưu trữ có đơn giá thấp hơn dành cho snapshots ít khi cần phục hồi, như backup dài hạn.

Tiêu chíSnapshot StandardSnapshot Archive
Mục đíchBackup thường xuyên, cần phục hồi sớmBackup dài hạn, hiếm khi phục hồi
Đơn giá lưu trữCao hơnThấp hơn; có thêm phí restore
Cách lưuIncremental: lưu các block thay đổi sau snapshot đầuFull snapshot: toàn bộ block có dữ liệu tại thời điểm snapshot
Tạo volumeCó thể dùng trực tiếp để tạo volumePhải restore về Standard trước, có thể mất tới 72 giờ

Xóa hoặc restore vĩnh viễn về Standard trước 90 ngày vẫn phải trả phí Archive cho thời gian còn lại. Vì Archive lưu full snapshot, dung lượng tính phí có thể lớn hơn bản incremental; cần xét cả dung lượng và phí restore.

3. AMI

AMI: mẫu tạo EC2: OS, phần mềm, cấu hình và thông tin disk.

Với EBS-backed AMI, dữ liệu disk nằm trong EBS snapshots.

Cài và cấu hình EC2 → tạo AMI → Launch Template → ASG tạo máy giống nhau

AMI có phạm vi Region; copy sang Region khác trước khi dùng ở đó. Cập nhật AMI và bản vá định kỳ, không để secret trong image.

4. Amazon Data Lifecycle Manager (DLM)

Amazon DLM tự động tạo, giữ lại và xóa EBS snapshots / EBS-backed AMIs theo policy; không cần tự viết Lambda hoặc cron cho lịch backup đơn giản.

EC2 + EBS volume

EBS snapshot
↓ giữ 7 ngày
Tự xóa snapshot hết hạn
Chức năngÝ nghĩa

RetentionGiữ theo số lượng bản hoặc thời gian, tùy policy

5. Mã hóa EBS

KMS bảo vệ volume, snapshot và dữ liệu truyền giữa EC2/EBS.
Snapshot từ volume đã mã hóa cũng được mã hóa; volume tạo từ encrypted
snapshot giữ encryption.

Không bật encryption trực tiếp trên volume cũ chưa mã hóa: snapshot → copy snapshot có mã hóa → tạo encrypted volume mới → thay volume.

Role cần quyền KMS để sử dụng key.

6. Use cases

Use cases: Golden AMI cho ASG; snapshot/copy cross-Region cho DR; Recycle Bin chống xóa nhầm; chuyển disk legacy sang encrypted volume bằng snapshot.

Nhớ nhanh · SAA-C03

Snapshot là backup disk; AMI là mẫu launch EC2. DLM tự quản lifecycle snapshot/AMI do chính DLM tạo; encryption và cross-account copy cần quyền KMS phù hợp.

EBS vs EFS vs Instance Store

Mục đích: Phân biệt disk riêng, file dùng chung và disk tạm để không chọn sai nơi lưu dữ liệu.

Ba cách lưu dữ liệu:

EBS = block volume cho EC2
EFS = shared file system
Instance Store = disk tạm trên host

1. So sánh chính

Tiêu chíEBSEFSInstance Store
KiểuBlock disk qua mạngShared file system NFS/POSIXLocal block disk trên host
Chia sẻThường một EC2; Multi-Attach có điều kiệnNhiều Linux client cùng mountGắn với instance/host
Phạm viMột AZRegional đa AZ hoặc One ZoneMột host

Dùng choBoot disk, databaseShared content, home directory, containersCache, buffer, scratch

2. EFS hoạt động thế nào?

Tạo mount target trong AZ, cho phép NFS 2049 qua SG rồi mount từ Linux client. EFS tự tăng/giảm dung lượng theo file, không cần cấp size volume trước.

Regional EFS lưu qua nhiều AZ để chịu lỗi tốt hơn.

One Zone rẻ hơn nhưng không chịu mất cả AZ.

Mã hóa at rest dùng KMS; có thể bật mã hóa in transit và dùng access point để giới hạn đường dẫn/quyền.

3. Performance và chi phí EFS

General Purpose hợp phần lớn ứng dụng nhạy latency. Max I/O là lựa chọn cho một số workload song song rất lớn, có latency cao hơn.

Elastic throughput tự điều chỉnh theo tải; Provisioned đặt mức throughput riêng; Bursting gắn khả năng throughput với dữ liệu lưu và burst credits.

Lifecycle có thể chuyển file sang IA/Archive để giảm phí lưu, đổi lại có phí truy cập và điều kiện theo lớp.

4. Instance Store

Rất nhanh vì disk ở gần compute.
Dữ liệu có thể còn sau reboot nhưng mất khi stop, hibernate, terminate hoặc
hardware lỗi.
Không lưu bản duy nhất của dữ liệu quan trọng; dùng backup/replication hoặc
nguồn dữ liệu khác.

5. Use cases

Use cases: WordPress hoặc nhiều ECS tasks cần cùng thấy file: EFS. Database riêng trên một EC2: EBS. Xử lý dữ liệu trung gian có thể tạo lại: Instance Store. Windows SMB share: xem FSx for Windows File Server.
