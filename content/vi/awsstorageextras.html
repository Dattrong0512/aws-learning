AWS Snow Family

Mục đích: Hiểu cách chuyển dữ liệu bằng thiết bị vật lý khi truyền qua mạng mất quá lâu hoặc nơi làm việc thiếu kết nối.

1. Vì sao dùng thiết bị?

Hàng trăm TB qua đường truyền chậm có thể mất nhiều tuần/tháng. Snowball Edge cho chép dữ liệu tại chỗ rồi vận chuyển thiết bị tới AWS để import vào S3.

Tạo job → nhận thiết bị → copy dữ liệu → gửi lại AWS → import vào S3

So sánh thời gian truyền mạng với thời gian nhận/copy/gửi/import; còn phải xét băng thông thực tế, chi phí và deadline.

2. Snowball Edge và edge compute

Storage Optimized ưu tiên dung lượng; Compute Optimized ưu tiên xử lý tại nơi tạo dữ liệu.

Edge compute hợp lọc dữ liệu, inference hoặc xử lý media ở site ít Internet trước khi đưa dữ liệu lên cloud.

Dữ liệu trên thiết bị được mã hóa; quản lý key, job credential và vận chuyển vẫn là phần quan trọng của quy trình.

3. Import và archive

Import vào S3 rồi dùng Lifecycle chuyển sang lớp Glacier phù hợp, không chọn đường “Snowball import trực tiếp vào Glacier vault”.

Không dùng thiết bị cho đồng bộ liên tục cần cập nhật thường xuyên; online recurring copy hợp DataSync hơn.

4. Lưu ý availability hiện tại

Từ 7/11/2025, Snowball Edge chỉ còn cho khách hàng hiện hữu.

Snowcone/Snowmobile trong tài liệu cũ không phải lựa chọn mới luôn sẵn có.

Giữ khái niệm offline migration để học, nhưng khi triển khai cần kiểm tra dịch vụ/giải pháp hiện được cung cấp. AWS Snowball availability.

5. Use cases

Use cases: Data center có nhiều dữ liệu và WAN hạn chế: offline bulk transfer nếu đủ điều kiện. Site disconnected cần xử lý tại chỗ: edge compute. NAS có kết nối đủ tốt và cần copy theo lịch: DataSync.

Nhớ nhanh · SAA-C03

Snow Family dùng di chuyển/processing dữ liệu quy mô lớn khi đường mạng không phù hợp; chọn thiết bị theo data size và yêu cầu edge compute.

Amazon FSx managed file systems

Mục đích: Chọn managed file system có protocol và tính năng phù hợp ứng dụng hiện có.

Các loại file system: FSx for Windows File Server · FSx for Lustre · FSx for NetApp ONTAP · FSx for OpenZFS

1. Bảng chọn FSx

LoạiProtocol/điểm mạnhPhù hợp
Windows File ServerSMB, NTFS, Active DirectoryWindows share, home directory, app Windows
LustreParallel file system, tích hợp S3HPC, ML training, media processing
NetApp ONTAPNFS/SMB/iSCSI, tính năng ONTAPNAS/NetApp migration, multi-protocol
OpenZFSNFS, snapshot/clone/compression ZFSWorkload Linux/ZFS cần latency thấp

2. Windows File Server

Tích hợp AD, file permissions/ACL và user quotas. Linux client cũng có thể mount SMB; đây không phải dịch vụ chỉ dành cho EC2 Windows.

Multi-AZ deployment tăng HA; backup bảo vệ dữ liệu.
On-prem truy cập qua VPN/DX với route, SG và quyền file phù hợp.
Windows SMB share thường chọn FSx Windows thay EFS NFS.

3. Lustre và S3

Lustre giúp nhiều compute nodes xử lý file song song với throughput cao. Có thể liên kết dataset trong S3, đọc dưới dạng file và xuất kết quả về S3.

Scratch dành cho xử lý tạm, không replicate dữ liệu để bảo vệ lỗi file server như Persistent. Persistent hợp dữ liệu cần giữ và workload dài hơn. Chọn deployment theo durability và tính năng được hỗ trợ, không coi mọi FSx đều có cùng mô hình HA.

4. ONTAP và OpenZFS

ONTAP phù hợp ứng dụng đang dựa vào NetApp, nhiều protocol, snapshots/clones và tiering. OpenZFS phù hợp ứng dụng ZFS/NFS và các tính năng snapshot/clone tương ứng.

Clone nhanh không thay backup độc lập. Mã hóa at rest dùng KMS; encryption in transit và file permissions phụ thuộc protocol/filesystem.

5. Use cases

Use cases: Company Windows share + AD: FSx Windows. HPC đọc dataset S3: Lustre. Lift-and-shift NetApp NAS: ONTAP. Workload đang dùng ZFS: OpenZFS. Shared Linux file phổ thông đa AZ: so sánh EFS trước.

6. Tích hợp S3, Single-AZ/Multi-AZ & Tầng lưu trữ của 4 dòng FSx

Dòng FSxSingle-AZ / Multi-AZTùy chọn lưu trữCách tích hợp S3
FSx for Windows File ServerCả haiSSD / HDDSao chép dữ liệu qua AWS DataSync
FSx for LustreSingle-AZ (file server)SSD / HDD / Intelligent-TieringLiên kết gốc Data Repository Association (DRA) tự import metadata & export kết quả HPC về S3
FSx for NetApp ONTAPCả haiSSD + Capacity Pool (Auto Tiering)Gắn S3 Access Points (đọc/ghi qua S3 API trong khi dữ liệu vẫn nằm trên FSx)

FSx for Lustre Intelligent-Tiering tự chuyển dữ liệu qua 3 tầng: Frequent Access (< 30 ngày) → Infrequent Access (≥ 30 ngày) → Archive Instant Access (≥ 90 ngày); dữ liệu của chế độ này có độ bền đa AZ nhưng thành phần file server Lustre vẫn chạy Single-AZ.

Nhớ nhanh · SAA-C03

FSx for Windows = SMB/AD; FSx for Lustre = HPC; FSx for NetApp ONTAP và OpenZFS phục vụ các nhu cầu file system khác.

AWS Storage Gateway

Mục đích: Cho ứng dụng on-prem dùng giao thức file/block/tape quen thuộc với storage ở AWS.

1. Gateway và local cache

Gateway: appliance nối ứng dụng tại chỗ với cloud.

Local cache giữ dữ liệu dùng gần đây để truy cập nhanh; dữ liệu được truyền lên AWS theo cơ chế gateway.

Storage Gateway phục vụ hybrid access liên tục. Nó khác DataSync chạy transfer job và Snowball chuyển dữ liệu bằng thiết bị.

2. S3 File Gateway

App on-prem --NFS/SMB--> File Gateway + cache --HTTPS--> S3 objects

App thấy file share, S3 lưu object. Gateway có IAM role truy cập bucket; SMB có thể dùng AD. Quyền share/file và quyền S3 là các lớp cần cấu hình.

Không coi cache local là nơi chứa mọi dữ liệu vĩnh viễn hoặc file gateway là shared POSIX filesystem giống EFS.

3. Volume Gateway

Cung cấp block volumes qua iSCSI. Cached volumes giữ dữ liệu chính ở AWS, cache phần đang dùng tại chỗ để giảm storage local. Stored volumes giữ toàn bộ dữ liệu chính tại chỗ và backup lên AWS.

Backup dùng EBS snapshots để phục vụ restore.

Stored hợp khi cần truy cập toàn bộ dataset với độ trễ local; cached hợp khi muốn giảm dung lượng on-prem.

4. Tape Gateway

Cung cấp iSCSI virtual tape library (VTL) cho phần mềm backup hiện có. Tape lưu trên AWS, có thể archive vào Glacier Flexible Retrieval/Deep Archive theo cấu hình.

Không phải mua và vận chuyển physical tape nữa; restore tape archive vẫn có thời gian/chi phí retrieval cần tính.

5. Use cases

Use cases: NFS/SMB share backed by S3: File Gateway. Block storage on-prem với cloud backup: Volume Gateway. Thay tape library nhưng giữ backup software: Tape Gateway.

6. So sánh Volume Gateway: Cached Volumes vs Stored Volumes

Tiêu chíCached VolumesStored Volumes

AWS DataSync & Transfer Family

Mục đích: Phân biệt copy dữ liệu giữa hệ storage với endpoint nhận file từ người dùng/đối tác.

1. DataSync

DataSync chạy task chuyển dữ liệu giữa storage hỗ trợ như NFS/SMB/HDFS/object storage và S3/EFS/FSx. Có scheduling, kiểm tra dữ liệu, bandwidth limit và truyền qua TLS.

NAS on-prem → DataSync agent/task → S3 / EFS / FSx
On-prem file storage thường cần agent; AWS-to-AWS trong cùng account thường
không cần agent.
Một số nguồn cloud/cross-account có quy tắc khác theo location và task mode.

2. Metadata và sync

Có thể giữ permissions/metadata được hỗ trợ theo cặp source/destination. Copy NFS sang S3 không biến S3 thành POSIX filesystem có đầy đủ quyền file như nguồn.

Đây là transfer task chạy theo lịch hoặc yêu cầu, không phải database CDC hay filesystem replication real-time. AWS metadata behavior.

3. Transfer Family

Managed endpoint cho client dùng SFTP/FTPS/FTP để truyền file tới S3/EFS theo protocol hỗ trợ; AS2 phục vụ trao đổi B2B với backend hỗ trợ riêng.

Đối tác dùng SFTP client → Transfer Family → S3 prefix được cấp quyền
Xác thực có thể service-managed, AD hoặc custom provider tùy protocol.
IAM role/policy và quyền filesystem giới hạn nơi từng user được truy cập.
FTP không mã hóa và chỉ dùng endpoint VPC; không chọn FTP cho file nhạy cảm
qua Internet.

4. Chọn theo tác vụ

Yêu cầuChọn
Copy NAS lớn sang AWS, có schedule/verificationDataSync
Đối tác vẫn dùng SFTP client để gửi fileTransfer Family
App tại chỗ tiếp tục dùng hybrid file/block/tapeStorage Gateway
Chỉ cần đường mạng riêngVPN/Direct Connect; còn cần công cụ transfer

5. Use cases

Use cases: Migration NFS → EFS: DataSync. Đồng bộ file theo lịch: DataSync. Thay SFTP server tự quản, dữ liệu vào S3: Transfer Family.

AWS storage selection guide

Mục đích: Chọn storage theo cách ứng dụng truy cập dữ liệu trước, rồi xét độ bền, latency và chi phí.

Chọn theo cách ứng dụng đọc/ghi:

Block → EBS
Shared File → EFS / FSx
Object → S3
Local temporary disk → Instance Store

1. Block, file hay object?

Nhu cầuDịch vụ
Object/API, data lake, static assets, backupS3
Disk cho EC2, boot hoặc databaseEBS
File NFS/POSIX dùng chung cho nhiều Linux clientsEFS
SMB/AD hoặc specialized file systemFSx
Local disk rất nhanh, dữ liệu tạo lại đượcInstance Store

Đừng chọn S3 như disk mount cho database cần block I/O. Đừng chọn EBS để nhiều app qua các AZ cùng chia sẻ file. Archive object: chọn lớp S3 Glacier theo thời gian retrieval cần thiết.

2. Dữ liệu nằm ở đâu và có thể mất không?

EBS ở một AZ, muốn sang AZ khác cần snapshot/restore.
Regional EFS qua nhiều AZ; One Zone giảm phí nhưng chấp nhận rủi ro AZ.
Instance Store mất dữ liệu theo vòng đời instance/host.
FSx có các deployment khác nhau; kiểm tra HA/backup của loại cụ thể.
Backup chống xóa nhầm; replication/failover phục vụ availability, không thay
thế lẫn nhau.

3. Hybrid access hay migration?

Tác vụDịch vụ
Tiếp tục file/block/tape tại on-prem, backend AWSStorage Gateway
Online bulk copy/sync có verificationDataSync
Nhận file SFTP/FTPS từ đối tácTransfer Family
Offline bulk transferSnowball/giải pháp physical transfer còn được cung cấp

4. Use cases

Use cases: Windows shared drive: FSx Windows. WordPress nhiều EC2: EFS. Disk DB riêng: EBS io2/gp3 theo I/O. Data lake: S3. Trước khi chốt, kiểm tra RPO/RTO, throughput, encryption và transfer/retrieval cost.

Nhớ nhanh · SAA-C03

Block storage → EBS; shared NFS → EFS; SMB/FS chuyên biệt → FSx; object/backup → S3; di chuyển dữ liệu → DataSync/Snow.
