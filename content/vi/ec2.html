Amazon EC2 fundamentals & launch configuration

Mục đích: Chạy máy chủ ảo khi cần tự kiểm soát hệ điều hành, phần mềm và cách ứng dụng hoạt động.

1. EC2 là gì?

EC2 cho thuê compute theo nhu cầu. AWS quản lý hạ tầng vật lý; bạn quản lý OS, bản vá, phần mềm và dữ liệu của ứng dụng trên máy.

Một instance nằm trong một AZ. Muốn chịu lỗi AZ, cần nhiều instance qua nhiều AZ; một máy lớn không tự tạo High Availability.

2. Các lựa chọn khi tạo máy

Thành phầnQuyết định điều gì

Instance typeCPU, RAM, mạng và khả năng I/O
VPC/subnetMáy nằm ở đâu và có đường mạng nào
Security GroupTraffic được phép vào/ra
IAM roleQuyền ứng dụng gọi dịch vụ AWS

Key pairDùng khi đăng nhập SSH; có thể quản trị bằng Systems Manager nếu cấu hình phù hợp

3. User Data

User Data thường là script cài package, tải cấu hình hoặc khởi động ứng dụng.
Trên Linux, mặc định script chạy với quyền root ở lần boot đầu; có thể cấu
hình chạy lại.

Không đặt secret trực tiếp trong User Data. Khi cần, ứng dụng lấy secret từ Secrets Manager/Parameter Store bằng role có quyền giới hạn.

4. Ghép thành ứng dụng có thể mở rộng

Người dùng → ALB → EC2 trong Auto Scaling Group ở nhiều AZ
                   └─ dữ liệu bền vững ở database/storage phù hợp

Launch Template lưu cấu hình tạo instance để ASG có thể tạo lại máy nhất quán. CloudWatch theo dõi tải; ASG điều chỉnh số máy.

5. CloudWatch monitoring

6. Use cases

Use cases: Web/API cần package riêng; ứng dụng legacy cần kiểm soát OS; batch hoặc HPC cần loại CPU/GPU cụ thể. Dùng tag để quản lý và xem chi phí theo môi trường.

EC2 nằm trong một AZ; muốn high availability cần nhiều máy qua nhiều AZ. User Data lo khởi tạo, IAM Role lo quyền truy cập AWS API.

EC2 instance types, lifecycle & Hibernate

Mục đích: Chọn cấu hình máy và cách dừng máy phù hợp với tài nguyên, thời gian khởi động và dữ liệu cần giữ.

1. Chọn instance family

FamilyPhù hợp
T/M – general purposeWeb, dev/test; T dùng CPU credits cho tải burst
C – compute optimizedXử lý nặng CPU, encoding, batch
R/X – memory optimizedIn-memory database, dataset lớn trong RAM
I/D – storage optimizedLocal I/O hoặc dữ liệu lớn trên disk
P/G – accelerated computingGPU, ML hoặc đồ họa

Tên m5.2xlarge gồm family M, thế hệ 5 và size 2xlarge.

Không cần học thuộc bảng vCPU của từng máy; chọn theo điểm nghẽn CPU, RAM, I/O hoặc mạng.

2. Reboot, Stop và Terminate

Thao tácĐiều gì xảy ra?
RebootKhởi động lại OS; giữ instance và storage.
StopDừng EBS-backed instance: giữ EBS, mất RAM và Instance Store. Public IPv4 tự cấp thường đổi khi Start lại.
TerminateXóa instance. EBS có DeleteOnTermination sẽ bị xóa; volume không bật thuộc tính này vẫn còn và tiếp tục tính phí.

Lưu ý: Stop không miễn phí EBS.

3. Hibernate

Hibernate ghi RAM vào encrypted EBS root volume rồi dừng máy.

Khi start, RAM và process được nạp lại, phù hợp ứng dụng mất nhiều thời gian chuẩn bị dữ liệu trong bộ nhớ.

RAM → EBS root được mã hóa → dừng → start → nạp lại RAM

Phải bật hỗ trợ hibernation khi launch, dùng loại máy/AMI hỗ trợ và root đủ chỗ cho RAM.

Không giữ hibernate quá 60 ngày; Instance Store vẫn mất dữ liệu. Chi tiết giới hạn theo OS.

4. Use cases

Use cases: C-family cho video encoding; R-family cho xử lý dữ liệu trong RAM. Hibernate cho môi trường dev hoặc ứng dụng khởi động chậm; dùng Multi-AZ và backup để bảo vệ availability/dữ liệu.

Nhớ nhanh · SAA-C03

Reboot giữ instance; Stop giữ EBS nhưng mất RAM; Terminate xóa instance theo cấu hình disk. Hibernate lưu RAM vào encrypted EBS để khôi phục trạng thái.

EC2 networking, Security Groups & IAM

Mục đích: Kiểm soát kết nối mạng và quyền truy cập AWS của ứng dụng trên EC2.

1. Security Group

Security Group là firewall stateful gắn với ENI.
Chỉ có Allow rule; rule của nhiều SG được cộng lại.
SG mới mặc định không cho inbound và cho outbound; response của kết nối được
phép tự đi qua.
Internet → ALB SG: HTTPS 443
ALB → App SG: chỉ cho nguồn là ALB SG
App → DB SG: chỉ cho nguồn là App SG trên port database

Tham chiếu SG giúp không phải cập nhật IP khi ASG thay máy.

Timeout có thể do SG, NACL hoặc route; connection refused thường do không có dịch vụ lắng nghe ở port đó.

2. Public và private IP

Private IP dùng trong mạng VPC.

EC2 truy cập Internet trực tiếp cần public IP cùng route tới Internet Gateway và rule mạng phù hợp; chỉ nằm trong public subnet chưa đủ.

Private instance có thể ra Internet qua NAT hoặc gọi dịch vụ AWS qua VPC
Endpoint.
SSH thường dùng 22, HTTPS 443, RDP 3389; nên giới hạn nguồn quản trị hoặc dùng
Systems Manager.

3. ENI và Elastic IP

ENI: card mạng ảo chứa private IP, MAC và SG, thuộc một AZ.

Secondary ENI có thể chuyển giữa instance trong cùng AZ; primary ENI không được tháo khỏi instance đang dùng.

Elastic IP là public IPv4 cố định có thể gắn lại sang tài nguyên khác.
Public IPv4 có phí; ưu tiên ALB/DNS nếu không cần IP cố định.
Quota EIP mặc định thường là 5 mỗi Region, có thể xin tăng.

4. Enhanced Networking và EFA

Elastic Fabric Adapter (EFA) là network interface dành cho EC2 chạy HPC hoặc distributed ML, giúp các instances trao đổi dữ liệu với latency thấp và throughput cao.

Cơ chếChức năng
Enhanced Networking / ENASR-IOV giúp tăng bandwidth/PPS và giảm latency cho mạng IP thông thường. ENA là lựa chọn hiện đại; Intel 82599 VF là legacy.
EFAThêm OS-bypass qua Libfabric cho ứng dụng MPI/NCCL tương thích; hợp tightly coupled workloads cần trao đổi dữ liệu liên tục.

Cần instance type, OS, driver/library và Security Group được EFA hỗ trợ. Dùng cho mô phỏng HPC nhiều node hoặc huấn luyện ML phân tán.

5. IAM role cho EC2

Instance profile đưa IAM role vào EC2.
SDK lấy credential tạm thời qua metadata service; bật IMDSv2 và cấp quyền tối
thiểu.
Không lưu access key cá nhân trên máy.

Network permission và IAM permission là hai lớp riêng: mở port không cấp quyền đọc S3; cấp role không tạo route mạng.

6. Use cases

Use cases: EC2 private đọc S3 bằng role và S3 VPC Endpoint. ALB nhận HTTPS từ người dùng, EC2 chỉ nhận request từ ALB SG, database chỉ nhận từ app SG.

7. Phân biệt chi tiết ENA vs EFA (Networking & HPC)

Tiêu chíENA (Elastic Network Adapter)EFA (Elastic Fabric Adapter)
Mục đích chínhEnhanced Networking chuẩn cho EC2 (băng thông cao, PPS lớn)HPC & Distributed AI/ML đa node liên kết chặt
Cơ chế truyềnĐi qua TCP/IP stack của hệ điều hànhHỗ trợ OS-bypass qua Libfabric và giao tiếp MPI để giảm tối đa độ trễ
Nhớ nhanh · SAA-C03

Security Group là stateful firewall cho ENI; IAM Role cấp quyền AWS API, không thay cho route hay network rules. HPC nhiều node trao đổi nhanh → cân nhắc EFA.

EC2 purchasing & placement strategies

Mục đích: Giảm chi phí và chọn cách đặt máy phù hợp với latency, khả năng chịu lỗi hoặc yêu cầu license.

Chọn cách mua theo workload:

On-Demand = linh hoạt
Savings Plans / Reserved Instances = cam kết để giảm giá
Spot = giá thấp, phải chịu gián đoạn
Capacity Reservation = giữ capacity

1. Chọn cách trả tiền

Lựa chọnKhi dùng
On-DemandTải khó đoán, ngắn hạn, không muốn cam kết
Reserved InstancesTải ổn định, cam kết 1 hoặc 3 năm; Standard/Convertible có mức linh hoạt khác nhau
Savings PlansCam kết mức chi tiêu mỗi giờ trong 1 hoặc 3 năm
SpotTải chịu được gián đoạn, có retry/checkpoint
Capacity ReservationCần giữ capacity tại một AZ, không tự có giảm giá
Dedicated InstanceCần hardware cách ly với account khác
Dedicated HostCần kiểm soát host vật lý hoặc license theo socket/core

Compute Savings Plans linh hoạt qua family/Region và cả Fargate/Lambda; EC2 Instance Savings Plans gắn với family và Region, linh hoạt size/OS/tenancy.

Regional RI và Zonal RI

Scope của RIGiảm giáGiữ capacity
Regional RIÁp dụng trong Region; có size flexibility cho Linux/UNIX, default tenancy khi phù hợpKhông
Zonal RIÁp dụng cho cấu hình EC2 khớp trong AZ đã chọn; không có AZ/instance-size flexibilityCó, cho cấu hình cụ thể trong một AZ

Standard/Convertible là offering class; Regional/Zonal là scope, hai cách phân loại khác nhau.

2. Spot cần thiết kế chịu gián đoạn

Spot dùng capacity còn trống và có thể bị AWS thu hồi.

Thông báo gián đoạn thường có trước khoảng 2 phút; không coi đó là thời gian luôn được đảm bảo cho mọi hành vi gián đoạn.

Dùng nhiều instance type/AZ, checkpoint và lưu dữ liệu bền vững bên ngoài
instance.
Phù hợp batch, CI và worker có thể chạy lại; kém phù hợp công việc không thể
gián đoạn.

3. Giữ capacity khác với giảm giá

Capacity Reservation đảm bảo capacity trong AZ đã chọn; vẫn trả tiền cho phần được giữ dù chưa dùng.

Có thể kết hợp mức giảm giá phù hợp từ RI/Savings Plans; Regional RI/Savings Plans không tự giữ capacity; Zonal RI giữ capacity cho cấu hình khớp trong AZ đã chọn.

4. Placement Groups

StrategyCách đặt máyĐánh đổi
ClusterGần nhau trong một AZLatency thấp, throughput cao; không chịu lỗi cả AZ
SpreadTách hardware cho từng máy, có thể nhiều AZCách ly nhóm nhỏ máy quan trọng; tối đa 7 running instances/AZ với rack-level spread
PartitionTách nhóm rack thành partitionHợp Kafka/HDFS/Cassandra; tối đa 7 partition/AZ

5. Use cases

Use cases: HPC cần các node trao đổi rất nhanh: Cluster. Các node quan trọng cần cách ly lỗi hardware: Spread. Hệ phân tán lớn tự replicate dữ liệu: Partition. Batch chạy lại được: Spot kết hợp checkpoint.

6. Phân biệt Regional RI vs Zonal RI & Offering Class

Thuộc tính RI (1 hoặc 3 năm)Phân biệt cốt lõi
Regional RI vs Zonal RIRegional RI linh hoạt AZ và instance size trong cùng family nhưng không giữ capacity; Zonal RI gắn một AZ cụ thể và có giữ chỗ capacity
Standard RI vs Convertible RIStandard giảm giá sâu hơn nhưng hạn chế đổi instance family; Convertible giảm ít hơn nhưng đổi sang instance family/OS/tenancy khác có giá trị tương đương hoặc cao hơn
Nhớ nhanh · SAA-C03

Spot tiết kiệm nhưng có thể gián đoạn; Savings Plans/Regional RI giảm giá chứ không tự giữ capacity. Cluster/Spread/Partition là ba cách phân bố instance khác nhau.

EC2 Storage Options

Mục đích: Chọn disk bền vững, disk tạm hoặc file dùng chung cho EC2.

1. So sánh storage

StorageĐặc điểm chính
EBSBlock storage qua mạng, cùng AZ với EC2. Giữ dữ liệu khi stop; terminate xóa hay giữ tùy DeleteOnTermination, root mặc định thường bị xóa.
Instance StoreDisk local, I/O nhanh. Mất dữ liệu khi stop/hibernate/terminate hoặc host hỏng; reboot vẫn giữ. Chỉ chứa dữ liệu có thể tạo lại.
EFSManaged NFS/POSIX cho Linux, nhiều EC2 cùng mount. Regional EFS dùng chung qua nhiều AZ, dung lượng tự mở rộng.

2. EBS volume types

LoạiPhù hợp
gp3 / gp2 — SSDGeneral purpose. gp3: baseline 3.000 IOPS, 125 MiB/s; IOPS/throughput độc lập dung lượng. gp2: IOPS tăng theo size, có burst credits.
io1 / io2 Block Express — SSDDatabase cần IOPS cao, ổn định và latency thấp.
st1 — HDDBig data, warehouse, log; throughput cho I/O tuần tự thường xuyên.
sc1 — HDDDữ liệu ít truy cập, ưu tiên chi phí thấp.

Boot volume dùng SSD. EBS tính phí dung lượng đã provision, kể cả khi EC2 dừng.

Tính năng EBSĐiều kiện & Lưu ý
Multi-AttachChỉ hỗ trợ io1/io2, tối đa 16 EC2 Nitro cùng AZ; bắt buộc dùng ứng dụng và cluster-aware file system (không dùng EXT4/XFS thông thường để nhiều máy cùng ghi)
EncryptionKMS bảo vệ volume, traffic EC2–EBS và snapshots; không bật trực tiếp trên volume cũ chưa mã hóa mà phải tạo volume mới từ snapshot

3. Snapshots và AMI

Snapshot = backup EBS tại một thời điểm, các lần sau lưu block thay đổi
Chuyển AZ = snapshot → tạo volume tại AZ đích → attach EC2
AMI = mẫu OS/phần mềm/cấu hình để launch EC2; thuộc Region, có thể copy

Snapshot không cần detach, nhưng cần flush/pause ghi để nhất quán. Archive: restore 24–72 giờ; Recycle Bin: giữ snapshot xóa nhầm 1 ngày–1 năm; FSR: tránh chậm khi đọc block lần đầu, có phí riêng.

4. EFS

EC2 Linux → mount target trong AZ → EFS dùng chung. SG của mount target mở TCP 2049 từ SG EC2; mã hóa at rest bằng KMS, in transit bằng TLS.

Regional = nhiều AZ; One Zone = một AZ, chi phí thấp hơn
General Purpose = latency thấp
Elastic = throughput tự điều chỉnh; Provisioned = đặt riêng
Bursting = throughput theo dung lượng Standard và credits
Standard = truy cập thường xuyên; IA/Archive = ít truy cập
Lifecycle policies = tự chuyển class theo thời gian không truy cập

IA/Archive có phí truy cập; Archive yêu cầu Regional + Elastic throughput. One Zone hỗ trợ Standard/IA.

5. Use cases

Use cases: EBS gp3 cho boot/app; io2 cho database; Instance Store cho cache/scratch; Regional EFS cho thư mục upload WordPress dùng chung giữa nhiều EC2.

Chi tiết: trang EBS.

Nhớ nhanh · SAA-C03

EBS = block disk bền vững trong một AZ; EFS = shared file system; Instance Store = local disk tạm. Chọn theo độ bền và nhu cầu chia sẻ.
