3. EC2 vs Fargate

ECS + EC2 = bạn quản EC2 = instance type + patch + ASG + capacity

ECS + Fargate = AWS quản server = bạn chỉ chọn CPU/RAM cho Task

Nhớ:

EC2

Fargate

ECS Anywhere và External launch type

ECS Anywhere cho phép đăng ký server/VM on-premises hoặc bên ngoài AWS vào ECS cluster để quản lý containers bằng ECS.

External launch type (EXTERNAL) dùng để chạy ECS tasks/services trên những external instances này; bạn vẫn quản lý server, OS và capacity.

Server / VM ngoài AWS
↓ cài ECS Agent + SSM Agent, đăng ký cluster
ECS Cluster
↓ launch type: EXTERNAL
Container Tasks trên server ngoài AWS

Ví dụ: quản lý container xử lý dữ liệu tại nhà máy từ ECS mà dữ liệu vẫn ở on-premises.

AWS Fargate

Mục đích: AWS Fargate là compute serverless cho containers — dùng với ECS hoặc EKS. Bạn khai báo CPU/RAM của task/pod; AWS provision, patch và vận hành toàn bộ máy chủ nền.

Luồng chạy container:

Container image + CPU/RAM
↓ ECS Task / EKS Pod
Fargate
↓
AWS vận hành compute

1. Fargate không phải là gì?

🧠 Fargate không thay ECS/EKS. ECS/EKS là orchestration; Fargate chỉ là launch/compute type — cách bạn chạy container, không phải hệ điều phối.

2. Fargate vs EC2 launch type

Tiêu chíFargateEC2
Quản lý serverAWS lo hếtBạn quản lý
Đơn vị tính phíCPU/RAM của taskInstance giờ
Kiểm soát hạ tầngThấp (không SSH)Cao (SSH, tùy chỉnh)
Workload phù hợpNhỏ, không đều, serverlessLớn, ổn định, tối ưu chi phí

3. Fargate vẫn cần những gì?

VPC + Subnet — mỗi task có ENI riêng. Security Group — kiểm soát traffic vào/ra task. IAM role — task execution role + task role. Image — từ ECR hoặc registry khác. Logs — CloudWatch Logs (qua execution role).

4. Fargate + EFS

Fargate task có thể mount Amazon EFS để có persistent shared storage cho containers serverless — nhiều task đa AZ cùng đọc/ghi một file system.

5. Giới hạn cần nhớ

CPU/RAM phải là cặp được hỗ trợ. Ví dụ task 4 vCPU dùng 8–30 GB RAM; đây không phải mức tối đa của Fargate. .

Không SSH được vào hạ tầng nền.

Một số workload cần host-level control (vd custom kernel, GPU) → phải dùng EC2 launch type.

Fargate chỉ tính phí compute cho vCPU và Memory cấp phát trong đúng khoảng thời gian Task/Pod thực sự chạy (không trả tiền cho EC2 nhàn rỗi); storage mở rộng, data transfer và Load Balancer tính phí riêng.

Amazon ECR

Mục đích: Amazon ECR (Elastic Container Registry) là private Docker/OCI image registry do AWS quản lý — nơi lưu trữ container images cho ECS, Fargate hoặc EKS.

1. Luồng sử dụng điển hình

CI build image → push ECR (tag/digest) → ECS/EKS pull → container chạy

2. Điểm chính

Image được tham chiếu theo tag (vd :latest) hoặc digest (sha256 — bất biến, an toàn hơn).

Task execution role (ECS/Fargate) cần quyền ecr:GetAuthorizationToken + ecr:BatchGetImage để pull image.

Repository policy cùng IAM kiểm soát ai được push/pull, đặc biệt với cross-account. Lỗi pull còn có thể do thiếu NAT route hoặc ECR VPC endpoints.

Image scanning quét lỗ hổng bảo mật (basic scan hoặc Enhanced Scanning với Inspector).

Lifecycle policy tự dọn image cũ (vd giữ 5 image mới nhất, xóa phần còn lại) — tiết kiệm chi phí.

Có thể replicate image sang Region/account khác; production nên pin immutable tag hoặc digest thay vì phụ thuộc :latest.

Mã hóa at rest: AWS managed key hoặc KMS CMK.

3. Bảo mật

LớpCơ chế
Control planeIAM (tạo/sửa/xóa repository)
Data planeRepository policy + IAM (push/pull)
At restSSE với AWS managed key hoặc KMS CMK
In transitTLS (HTTPS)

4. Use cases

Use cases:

Repository cross-account với IAM/repository policy; scan lỗ hổng và dùng lifecycle policy dọn image cũ.

3. IAM và Kubernetes RBAC

🧠 IAM access không tự cấp Kubernetes permission. IAM cho phép bạn gọi EKS API (tạo cluster, describe…); nhưng quyền trong cluster (get pods, deploy…) do Kubernetes RBAC quyết định. Cần map IAM principal → Kubernetes role.

5. Fargate + EKS

Fargate dùng được với EKS qua Fargate profile (chọn namespace/label → pod chạy trên Fargate).

EKS vẫn là lớp control plane; workload phải tương thích Fargate capabilities (vd không chạy được daemonset trên Fargate).

6. Node groups, networking & persistent storage

1. EKS Node Management

  • Managed Node Group: AWS quản lý vòng đời EC2 Nodes và Auto Scaling Group (ASG).

  • Self-Managed Nodes: Tự quản lý EC2 Nodes, phù hợp khi cần tùy chỉnh sâu.

  • Multi-AZ: Phân bố Nodes ở Private Subnets thuộc nhiều AZ để tăng HA.

  • ALB/NLB: Cho phép truy cập ứng dụng từ bên ngoài.

  • NAT Gateway / VPC Endpoints: Cho Nodes/Pods truy cập Internet hoặc AWS Services khi cần.

2. EKS Storage

Kubernetes dùng PVC (PersistentVolumeClaim) để yêu cầu lưu trữ.

                            |
                            v
                      AWS Storage

Storage

Khi nào dùng?

EBS

Block Storage, gắn với EC2 Node trong cùng AZ

EFS

Shared File System đa AZ, nhiều Pods cùng truy cập

FSx

HPC, hiệu năng cao hoặc filesystem chuyên biệt

EKS Fargate Limitations

  • Không hỗ trợ EBS Volume: Dùng EFS nếu cần Persistent Shared Storage.

  • Không hỗ trợ DaemonSet: Không chạy workload yêu cầu quản lý trực tiếp host.

  • Không cần quản lý EC2 Nodes: AWS Fargate cung cấp compute.

Nhớ nhanh SAA-C03

  • Managed Node Group → AWS quản lý EC2 Nodes.

  • EKS EC2 + EBS → Persistent Block Storage.

  • EKS Fargate + EFS → Persistent Shared Storage.

  • HPC + EKS EC2 → FSx for Lustre.

  • Fargate → Không EBS, không DaemonSet.
