Amazon DocumentDB

Mục đích: Amazon DocumentDB là managed document database tương thích MongoDB API, dùng để lưu dữ liệu dạng JSON document với schema linh hoạt.

DocumentDB = Document Database = MongoDB-compatible = Managed by AWS

1. Document Model

Khác relational database: RDS / Aurora = Table = Row / Column = Schema rõ ràng

DocumentDB: Document = JSON-like object = mỗi document có thể có field khác nhau

Ví dụ:

Product A
{
  name: "Phone",
  color: "Black"
}

Product B
{
  name: "Laptop",
  ram: "16GB",
  cpu: "M3"
}

→ Không cần mọi record có cùng column.

2. MongoDB Compatibility

Application có thể dùng:

MongoDB Driver
↓
DocumentDB

Nhưng nhớ: DocumentDB ≠ MongoDB self-hosted

DocumentDB = AWS service tương thích MongoDB API

Nên vẫn cần kiểm tra feature MongoDB nào được hỗ trợ.

3. Managed Cluster

AWS quản: Provisioning · Patching · Backup · Replication · Storage scaling

Application vẫn phải lo: Document Design · Indexes · Queries · Security

4. Availability & Storage

DocumentDB có replication qua nhiều AZ:

Application
↓
DocumentDB Cluster
↓
Replicas across AZs

Mục tiêu: High Availability + Failover

Storage có thể tự mở rộng khi data tăng.

5. Index

Muốn query nhanh thì vẫn cần index.

Query theo email
↓
Index: email
↓
Search nhanh hơn

Nếu không có index phù hợp:

Full Scan
↓
Query chậm

Managed database không có nghĩa là query tự động tối ưu hết.

6. DocumentDB vs RDS vs Neptune

  • RDS / Aurora = SQL = relational = join nhiều table
  • DocumentDB = JSON document = schema linh hoạt = MongoDB-compatible
  • Neptune = Graph Database = relationship / traversal
Bank Transaction

→ Neptune

IAM dùng để quản AWS resource, còn quyền đọc/ghi dữ liệu database vẫn cần cơ chế authentication/authorization phù hợp.

9. Kích thước Document & DocumentDB Serverless

DocumentDB hỗ trợ kích thước một document tối đa 16 MB và có chế độ DocumentDB Serverless tự co giãn năng lực theo từng giây dựa trên DCU.

Nhớ nhanh · SAA-C03

Amazon Neptune

Mục đích: Amazon Neptune là managed graph database dùng khi dữ liệu có rất nhiều mối quan hệ và cần truy vấn các connection giữa chúng.

Neptune = Graph Database = Node + Relationship

1. Graph Model

Graph gồm: Node / Vertex = thực thể

Edge = quan hệ giữa các thực thể

Ví dụ:

User A
↓ FRIEND_OF
User B
↓ BOUGHT
Product X

Hoặc:

User
↓ LIKES
Post
↓ HAS_COMMENT
Comment

Neptune mạnh khi câu hỏi cần đi qua nhiều relationship.

2. Khi nào dùng Neptune?

Use cases:

User A
↓ friend
User B
↓ bought
Product X

Query: "Bạn của User A đã mua sản phẩm gì?"

Neptune có thể traverse graph trực tiếp thay vì phải join nhiều bảng.

Amazon Timestream

Mục đích: Amazon Timestream là serverless time-series database dùng để lưu và phân tích dữ liệu có timestamp.

Timestream = Time Series Database = Timestamp + Measurements

1. Time Series Data

Ví dụ:

10:00 → CPU = 40%
10:01 → CPU = 55%
10:02 → CPU = 80%

Hoặc IoT: Timestamp · DeviceId · Temperature · Humidity · Battery

Time là phần quan trọng nhất của dữ liệu.

2. Data Model

Một record thường có: Timestamp + Dimensions + Measures

Timestamp = 10:00 · Dimensions: · deviceId = sensor-01 · region = ap-southeast-1 · Measures: · temperature = 30 · humidity = 70

3. Multi-measure Record

Nếu nhiều measurement có cùng timestamp:

10:00 · Temperature = 30 · Humidity = 70 · Battery = 90%

có thể lưu chung: 1 Timestamp + nhiều Measures

→ giảm số lượng record/write.

4. Storage Tiering

Timestream tự chia dữ liệu:

Recent Data
↓
Memory Store
= query nhanh
Old Data
↓
Historical Storage
= rẻ hơn

Bạn vẫn có thể query cả hai.

5. Query

Timestream hỗ trợ SQL để phân tích theo thời gian.

CPU trung bình mỗi 5 phút · Temperature cao nhất hôm nay · Request latency trong 1 giờ qua

Time-series Data
