AWS encryption patterns & KMS

Mục đích: Hiểu 3 nơi encryption xảy ra và cách AWS KMS quản lý encryption key.

  • In Transit = mã hóa khi truyền
  • At Rest = mã hóa khi lưu
  • Client-Side = client tự mã hóa trước khi gửi

1. Encryption in Transit

TLS / SSL
↓
HTTPS

Client
↓ mã hóa
Internet
↓
AWS Service
↓ giải mã
Data

Bảo vệ khỏi: Eavesdropping · Man-in-the-Middle

Certificate giúp client xác thực endpoint.

2. Server-Side Encryption

Service tự mã hóa data trước khi lưu.

Client
↓ HTTPS
S3 / EBS / RDS
↓
Encrypt
↓
Ciphertext
↓
Storage

Khi đọc:

Storage
↓
Decrypt
↓
Client

AWS service sử dụng KMS key/data key để thực hiện encryption.

3. Client-Side Encryption

Client tự mã hóa trước:

Client
↓ Encrypt
Ciphertext
↓
S3 / DynamoDB / Storage

Storage chỉ giữ: Ciphertext

Chỉ client có key mới decrypt được.

Đây là lớp bảo vệ mạnh hơn nếu muốn dữ liệu vẫn được mã hóa ngay cả đối với administrator của storage service.

4. AWS KMS

KMS = quản lý encryption keys + kiểm soát quyền dùng key + audit key usage

KMS tích hợp với: S3 · EBS · RDS · SSM · CloudTrail · IAM · ...

Application không lấy plaintext KMS key ra.

Application
↓ KMS API
Encrypt / Decrypt
↓
KMS thực hiện crypto operation

5. KMS Key Types

  • Symmetric = cùng key để Encrypt / Decrypt = AWS service thường dùng
  • Asymmetric = Public Key + Private Key = Encrypt/Verify bằng public = Decrypt/Sign bằng private
  • Các loại key theo ownership: AWS Owned Key = AWS quản lý hoàn toàn
  • AWS Managed Key = AWS quản lý = alias dạng aws/service-name
  • Customer Managed Key = customer quản lifecycle + policy = kiểm soát chi tiết nhất

Customer Managed Key phù hợp khi cần custom key policy, cross-account, audit hoặc control lifecycle.

6. Key Policy

IAM Policy ≠ tự động có quyền dùng KMS Key

KMS cần: Key Policy

để xác định ai được dùng key.

Ví dụ:

Key Policy
↓
Allow Role A
↓
kms:Decrypt

Cross-account cũng thường cần cấu hình key policy phù hợp.

7. Rotation

AWS Managed Key
→ AWS tự rotation

Customer Managed Key
→ có thể bật automatic rotation

Imported key material có giới hạn rotation khác.

8. KMS Key theo Region

KMS key là Regional resource.

Region A · KMS Key A · Region B · KMS Key B

Khi copy encrypted snapshot sang Region khác:

Decrypt bằng Key A
↓
Encrypt bằng Key B
↓
Snapshot ở Region B

9. Multi-Region Key

MRK có: Primary Key + Replica Key

ở các Region khác nhau.

Chúng có cùng: Key ID · Key Material · Rotation Properties

→ thuận tiện cho client-side encryption cần decrypt ở nhiều Region.

MRK ≠ Global Resource

Primary và replica vẫn được quản lý theo từng Region.

10. Use cases

Use cases:

  • SSE-KMS cho S3/EBS/RDS khi cần CloudTrail audit, key policy và revoke access theo key.
  • Client-side encryption cho SSN/PII trước khi replicate qua DynamoDB Global Tables hoặc Aurora Global Database.
  • Customer managed key và key policy có điều kiện để chia sẻ encrypted snapshot/AMI cho account DR.

Mục đích: Dùng dedicated hardware HSM khi cần customer kiểm soát sâu hơn về key, user, permission và key material.

CloudHSM = dedicated Hardware Security Module = hardware dành riêng cho customer = customer quản key + user + permission

AWS WAF, Shield & Firewall Manager

Mục đích: Bảo vệ workload Internet-facing theo 3 lớp:

  • WAF = lọc HTTP request = Layer 7
  • Shield = bảo vệ DDoS
  • Firewall Manager = quản security policy tập trung cho nhiều AWS account/resource

1. AWS WAF

AWS WAF bảo vệ application ở: Layer 7 = HTTP / HTTPS

WAF có thể attach vào: Application Load Balancer · API Gateway · CloudFront · AppSync · Cognito User Pool

Không attach trực tiếp vào: Network Load Balancer

vì: NLB = Layer 4 = TCP / UDP

WAF = Layer 7 = HTTP

  • Ngoài ra: Size Constraint = kiểm tra kích thước request
  • Geo Match = lọc theo quốc gia
  • Rate-Based Rule = giới hạn request quá nhiều từ một source

Ví dụ:

Amazon GuardDuty, Inspector & Macie

Mục đích: Phân biệt 3 loại security finding:

1. Amazon GuardDuty, Inspector & Macie

  • GuardDuty = phát hiện threat / hành vi bất thường
  • Inspector = tìm vulnerability + network exposure
  • Macie = tìm sensitive data / PII trong S3

2. Amazon GuardDuty

GuardDuty là: Managed Threat Detection

Machine Learning · Anomaly Detection · Threat Intelligence

để phát hiện hành vi đáng ngờ.

Nguồn dữ liệu chính: CloudTrail · VPC Flow Logs · DNS Logs

Ví dụ phát hiện: Unusual API calls · Suspicious network traffic · Malicious IP · Cryptocurrency mining · Suspicious DNS activity

Có thêm protection cho một số service như:

EKS · RDS / Aurora · EBS Malware · Lambda · S3

Không cần cài agent trên workload.

AWS Logs / Activity
↓
GuardDuty
↓
Finding
↓
EventBridge / Security Hub
↓
SNS / Lambda / Workflow

GuardDuty = detect threat ≠ tự remediation

3. Amazon Inspector

Inspector dùng để tìm: Known Vulnerabilities + Network Reachability

Hỗ trợ: EC2 · ECR Container Images · Lambda

3.1. EC2

EC2
↓

↓
scan OS / packages
↓
compare CVE database

Có thể phát hiện: Outdated package · Known CVE · Unintended network exposure

3.2. ECR

↓

↓

3.3. Lambda

Lambda Code / Dependencies
↓

Inspector tạo: Finding + Risk Score

để ưu tiên remediation.

Inspector = tìm vulnerability ≠ tự patch / redeploy

4. Amazon Macie

Macie chuyên tìm: Sensitive Data · PII

trong: Amazon S3

Machine Learning · Pattern Matching

Ví dụ:

S3 Bucket
↓

↓

Có thể phát hiện dữ liệu như: Name · Email · Phone · ID / sensitive information

Macie: = discover sensitive data ≠ tự sửa Bucket Policy / IAM / encryption

Sau finding, team có thể: Block Public Access · Fix Bucket Policy · Enable Encryption · Delete unnecessary data

5. GuardDuty vs Inspector vs Macie

  • GuardDuty = hệ thống có đang bị attack / compromise không?
  • Inspector = workload có vulnerability không?
  • Macie = S3 có chứa sensitive data / PII không?

6. Amazon Security Lake

Amazon Security Lake tự động thu thập, chuẩn hóa và tập trung dữ liệu bảo mật vào Amazon S3 trong account của bạn để phân tích, điều tra sự cố và đối chiếu dữ liệu từ nhiều nguồn.

Security logs / events
AWS + on-premises + nguồn bên thứ ba
↓
Amazon Security Lake
↓ chuẩn hóa OCSF + Apache Parquet
Amazon S3
↓
Athena / công cụ phân tích / SIEM

Security Lake chuẩn hóa tự động các nguồn AWS tích hợp; custom sources phải gửi dữ liệu theo OCSF/Parquet yêu cầu. Đây là nền tảng tập trung dữ liệu bảo mật; GuardDuty, Inspector và Macie cung cấp các loại phát hiện tương ứng. ·

7. Use cases

Use cases:

  • EventBridge route GuardDuty cryptocurrency finding tới SNS on-call và Lambda cô lập instance theo runbook.
  • Inspector phát hiện CVE trong ECR image trước/đồng thời deployment; team patch image và redeploy immutable container.
  • Macie quét S3 data lake để tìm PII bị lưu nhầm, rồi áp S3 Block Public Access, least-privilege policy và SSE-KMS.
  • Security Lake gom CloudTrail, VPC Flow Logs và nguồn bảo mật khác vào S3 để điều tra sự cố bằng Athena hoặc SIEM.

AWS Security Hub, Amazon Detective & AWS Audit Manager

Mục đích: Tập trung hóa cảnh báo bảo mật, điều tra nguyên nhân gốc rễ sự cố và tự động thu thập bằng chứng kiểm toán tuân thủ.

1. Bảng phân biệt ba dịch vụ

Dịch vụCâu hỏi giải quyếtCơ chế chính
AWS Security HubTổng thể môi trường đang có những rủi ro và vi phạm chuẩn nào cần ưu tiên xử lý?Gom findings chuẩn hóa (ASFF) từ GuardDuty, Inspector, Macie, Firewall Manager, Config và chấm điểm tự động theo bộ chuẩn CIS, PCI-DSS, AWS FSBP
Amazon DetectiveSự cố bảo mật vừa phát hiện bắt nguồn từ đâu và phạm vi ảnh hưởng thế nào?Dựng đồ thị liên kết tự động từ CloudTrail, VPC Flow Logs, EKS audit logs và GuardDuty findings để điều tra nguyên nhân gốc (Root Cause Analysis)
AWS Audit ManagerLàm sao xuất bằng chứng tuân thủ cho kiểm toán viên mà không phải gom thủ công?Liên tục thu thập bằng chứng (Evidence) từ CloudTrail, Config, Security Hub và ánh xạ vào controls của PCI-DSS, HIPAA, GDPR, SOC 2 thành Assessment Report

2. Luồng phối hợp thực tế

GuardDuty / Inspector / Macie phát hiện bất thường
  ├─► AWS Security Hub   → Tổng hợp, chấm điểm tuân thủ & kích hoạt phản ứng qua EventBridge
  ├─► Amazon Detective   → Truy vết đồ thị hành vi tìm nguyên nhân gốc (Root Cause)
  └─► AWS Audit Manager  → Gom lịch sử API/cấu hình/findings thành báo cáo bằng chứng kiểm toán
