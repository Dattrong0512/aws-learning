Parquet và ORC là columnar format.

Ví dụ table có: Name · Age · Country · Salary · Email

SELECT Name, Salary · FROM employees;

Parquet: chỉ đọc: · Name · Salary

→ giảm data scanned.

Parquet / ORC = ít scan = nhanh hơn = rẻ hơn

8. Partition

Partition = chia data trong S3 thành các nhóm theo folder/prefix.

s3://logs/ · year=2026/ · month=09/ · day=29/

Athena hiểu: year · month · day

như các partition columns.

SELECT * · FROM logs · WHERE year = 2026 · AND month = 9;

Athena chỉ cần đọc: year=2026/month=09/

thay vì toàn bộ bucket.

9. Partition là Virtual Column

Ví dụ file Parquet bên trong không nhất thiết chứa:

Nhưng S3 path: /year=2026/month=09/day=29/

cho Athena biết: year = 2026 · month = 09 · day = 29

Partition value có thể đến từ S3 path, không nhất thiết nằm trong file.

10. Nếu không filter Partition

Giả sử: 2024/ · 2025/ · 2026/

SELECT * · FROM logs;

→ Athena có thể scan tất cả.

Nếu: WHERE year = 2026

→ chỉ scan partition 2026.

Streaming platforms: Amazon MSK & Managed Service for Apache Flink

Mục đích: Amazon MSK là managed Apache Kafka để truyền event stream theo topic/partition; Amazon Managed Service for Apache Flink (tên cũ Kinesis Data Analytics for Apache Flink) chạy ứng dụng Flink managed để xử lý stream real-time từ Kinesis Data Streams hoặc MSK.

↓

↓

1. Amazon MSK

Amazon MSK là Apache Kafka được AWS quản lý.

Thay vì tự: Cài Kafka · Quản broker · Patch · Recovery · Scaling

AWS quản phần infrastructure cho bạn.

MSK = Kafka API + Kafka ecosystem + Managed infrastructure

Cluster thường chạy trong VPC và có thể trải nhiều AZ để tăng HA.

2. Kafka Model

  • Kafka có 3 thành phần quan trọng: Producer = gửi event
  • Topic = luồng / loại event
  • Consumer = đọc event

Ví dụ:

Order Service
↓ Producer
Topic: orders
↓
Fraud Consumer
Analytics Consumer
Notification Consumer

Một event stream có thể được nhiều consumer xử lý độc lập.

3. Topic & Partition

Topic được chia thành: Partitions

orders topic
├── Partition 0
├── Partition 1
└── Partition 2

Partition giúp: Parallel Processing · Scale throughput

Consumer Group có thể chia partitions cho nhiều consumers:

Partition 0 → Consumer A
Partition 1 → Consumer B
Partition 2 → Consumer C

Topic = stream logic, Partition = đơn vị parallelism.

Kafka có thể thêm partition, nhưng không giảm partition count trực tiếp.

4. Producer & Consumer vẫn là code của bạn

MSK quản Kafka infrastructure, nhưng business logic vẫn do application xử lý.

Producer Code
↓
MSK
↓
Consumer Code
↓
Business Logic

MSK không tự hiểu: Order · Payment · Fraud · Customer

nó chỉ vận chuyển/lưu event.

5. Storage & Replication

Kafka record được lưu theo retention:

Producer
↓
Broker
↓
EBS Storage

Broker có thể replicate data:

Broker A
↓ replicate
Broker B
↓
Broker C

→ tăng durability và availability.

6. MSK Serverless

Hai cách chính: Provisioned MSK = chọn/quản broker capacity

MSK Serverless = AWS tự provision + scale capacity

Phù hợp Serverless khi: Traffic thay đổi nhiều · Không muốn capacity planning

Provisioned phù hợp khi cần kiểm soát cluster/capacity nhiều hơn.

AWS Data Pipeline, Amazon MWAA & AWS Data Exchange

Mục đích: Điều phối luồng công việc xử lý dữ liệu phức tạp theo lịch/phụ thuộc và tích hợp các bộ dữ liệu bên thứ ba lên AWS.

1. Amazon MWAA vs AWS Data Pipeline

Dịch vụVai trò & Điểm phân biệt
Amazon MWAA (Managed Workflows for Apache Airflow)Chạy môi trường Apache Airflow managed để điều phối data pipelines đa bước bằng mã Python (DAGs), xử lý phụ thuộc, retry và cảnh báo; bản thân MWAA chỉ điều phối, còn việc tính toán/lưu trữ do S3, Glue, EMR, Redshift đảm nhận
AWS Data PipelineDịch vụ điều phối di chuyển và biến đổi dữ liệu định kỳ giữa các kho dữ liệu AWS/on-premises theo điều kiện phụ thuộc
Amazon MWAA (DAG theo lịch) → kích hoạt AWS Glue ETL đọc S3 → nạp bảng Amazon Redshift → gửi thông báo SNS

2. AWS Data Exchange

AWS Data Exchange: chợ dữ liệu (data marketplace) giúp đăng ký (subscribe) các bộ dữ liệu thương mại/công khai từ nhà cung cấp bên thứ ba và nhận trực tiếp vào S3, Redshift, Lake Formation hoặc qua API mà không phải tự viết pipeline thu thập.
