Amazon Athena

Purpose: Amazon Athena is a serverless SQL query service to analyze data primarily located in Amazon S3 without needing to build a database/data warehouse server.

Athena = SQL + S3 + Serverless

The file is in S3

5. Data Scanned example

Let's say S3 has: 1 TB CSV data

Query: SELECT name · FROM users;

With CSV, Athena may have to read a lot of file data.

If the same data is saved using Parquet:

Athena just needs to read the column "name"

→ scan less.

6. Parquet / ORC

Parquet and ORC are columnar formats.

For example the table has: Name · Age · Country · Salary · Email

SELECT Name, Salary · FROM employees;

CSV: often have to read the entire row/file

Parquet: read only: · Name · Salary

→ reduce scanned data.

Parquet / ORC = less scans = faster = cheaper

7. Compression

Files can be compressed: gzip · Snappy · zstd · ...

Data
↓
Compression
↓
Smaller files
↓
Athena reads fewer bytes

→ can reduce cost and reading time.

8. Partition

Partition = divide data in S3 into groups according to folder/prefix.

s3://logs/ · year=2026/ · month=09/ · day=29/

Athena understands: year · month · day

as partition columns.

SELECT * · FROM logs · WHERE year = 2026 · AND month = 9;

Athena simply read: year=2026/month=09/

instead of the entire bucket.

9. Partition is Virtual Column

For example, the Parquet file inside does not necessarily contain:

But S3 path: /year=2026/month=09/day=29/

Tell Athena: year = 2026 · month = 09 · day = 29

Partition value can come from the S3 path, not necessarily in the file.

10. If not filter Partition

Suppose: 2024/ · 2025/ · 2026/

SELECT * · FROM logs;

→ Athena can scan everything.

If: WHERE year = 2026

→ only scan partition 2026.

3. Why is Redshift fast for Analytics?

Redshift is optimized with: Columnar Storage · MPP · Sort Key · Distribution

4. Columnar Storage

Data is stored in columns instead of rows.

Table example: Name · Age · Country · Salary

Query: SELECT Country, AVG(Salary) · FROM employees · GROUP BY Country;

Redshift mainly needs to read: Country · Salary

instead of the entire row.

Columnar = scan fewer columns = suitable for analytics

5. MPP

MPP = Massively Parallel Processing

Redshift divides the query into multiple compute nodes for parallel processing.

SQL Query
↓

↓

Compute Node 2
Compute Node 3
↓

↓
Result

MPP = multiple machines processing one large query.

6. Sort Key

Sort Key helps data to be sorted by columns commonly used for filtering.

Sort Key = OrderDate

WHERE OrderDate >= '2026-09-01'

→ Redshift can skip many unrelated data blocks.

Sort Key = reduce the data to be scanned

7. Distribution

Distribution decides how data is divided into compute nodes.

Data
↓
Compute Node 1
Compute Node 2
Compute Node 3

Objective: distribute workload evenly + Reduce data that must be moved when JOIN

Sort Key = how data is sorted. Distribution = which node the data is located at.

1. Amazon MSK

Amazon MSK is Apache Kafka is managed by AWS.

Instead of self: Install Kafka · Manage broker · Patch · Recovery · Scaling

AWS manages the infrastructure for you.

MSK = Kafka API + Kafka ecosystem + Managed infrastructure

Clusters usually run in VPC and can span multiple AZs to increase HA.

2. Kafka Model

  • Kafka has 3 important components: Producer = send event
  • Topic = stream / event type
  • Consumer = read event

3. Topic & Partition

Topics are divided into: Partitions

orders topic
├── Partition 0
├── Partition 1
└── Partition 2

Partition helps: Parallel Processing · Scale throughput

Consumer Group can divide partitions among multiple consumers:

Partition 0 → Consumer A
Partition 1 → Consumer B
Partition 2 → Consumer C

Topic = logical stream, Partition = parallelism unit.

Kafka can add partition, but does not reduce partition count directly.

AWS Data Pipeline, Amazon MWAA & AWS Data Exchange

Purpose: Orchestrate complex scheduled/dependent data processing workflows and integrate third-party data sets to AWS.

1. Amazon MWAA vs AWS Data Pipeline

ServiceRoles & Distinguishing Points
Amazon MWAA (Managed Workflows for Apache Airflow)Run environment Apache Airflow managed to orchestrate multi-step data pipelines using Python code (DAGs), handling dependencies, retries, and warnings; MWAA itself coordination only, while computation/storage is handled by S3, Glue, EMR, Redshift
AWS Data PipelineService that coordinates periodic data migration and transformation between AWS/on-premises data warehouses according to dependencies
Amazon MWAA (scheduled DAG) → enable AWS Glue ETL read S3 → load Amazon Redshift table → send SNS notification

2. AWS Data Exchange

AWS Data Exchange: data marketplace helps subscribe to commercial/public datasets from third-party providers and receive them directly into S3, Redshift, Lake Formation or via API without having to write your own collection pipeline.
