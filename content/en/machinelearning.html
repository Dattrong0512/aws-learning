Rekognition = understand image / video content

Image / Video

User uploads image

detect:

Image / Video

→ Flags

Purpose: These are available ML services for speech and language processing, without the need to train the model yourself.

Transcribe
= Speech → Text

Polly
= Text → Speech

Translate
= Text in language A → Text in language B

1. Amazon Transcribe

Transcribe used Automatic Speech Recognition (ASR) to convert audio to text.

Audio / Voice
↓
Transcribe
↓
Text Transcript

For example:

Customer Call
↓
Transcribe
↓
Call Transcript

Can be used for: Call transcript · Subtitle / Caption · Searchable video/audio

Also supports: Language Identification = language self-identification

PII Redaction = hide/delete personal information from transcript

2. Amazon Polly

Polly converts text to speech.

Text
↓
Polly
↓
Speech Audio
"Welcome to our application"
↓
Polly
↓
🔊 Voice

Reading can be customized with: Lexicon = correct the pronunciation of word / name / acronym

SSML = adjust pronunciation / emphasis / speaking style

Polly = Text-to-Speech.

3. Amazon Translate

Translate is used to translate text between languages.

English Text
↓
Translate

Vietnamese Text

Suitable for: Website localization · Product description · Notification · Multilingual Application

Amazon Lex & Amazon Connect

Purpose: Amazon Lex is used to create chatbots/voice bots that understand user intentions, while Amazon Connect is a cloud contact center to receive calls and coordinate contact flow.

Lex = understand speech/text = recognize intent

Connect = receive calls = coordinate contact flow

1. Amazon Lex

Lex uses:

ASR
= Speech → Text

NLU
= understand what the user wants to do

For example:

"I want to make an appointment for tomorrow"
↓
Lex
↓
Intent = BookAppointment

Intent = user intent, not just keywords.

Lex is suitable for: Chatbot · Voice Bot · Call Center Bot

2. Amazon Connect

Amazon Connect is cloud contact center.

Caller
↓
Amazon Connect
↓
Contact Flow
↓
Bot / Agent / Backend

Connect can: Receive calls · Route calls · Create contact flow · Switch to agent · Integrate CRM / AWS services

3. Connect + Lex + Lambda

Popular flows:

Caller
↓
Amazon Connect
↓
Amazon Lex
↓
Intent identification
↓
Lambda
↓
CRM/Backend

Scheduling example:

"I want to book a 3pm appointment"
↓
Connect
↓
Lex
→ Intent = BookAppointment
↓
Lambda
↓
CRM
↓
Create appointment

or
case has not been designed yet

Amazon SageMaker AI

Purpose: Amazon SageMaker AI is a managed service to build, train, tune, and deploy custom Machine Learning models.

SageMaker = Build ML Model = Train = Tune = Deploy = Predict

Different from available AI services such as Translate or Textract:

Translate / Textract = ready-made AWS model

SageMaker = you train your own model for your own problem

1. Basic ML Flow

Historical Data
↓
Features + Labels
↓
SageMaker Training
↓
Model
↓
New Data
↓
Prediction

For example:

Historical Students
↓
Study Time + Experience
↓
Exam Result
↓
Train Model
↓
New Student
↓
Predict Pass / Fail

2. Training Data

Training usually requires: Features = input information

Label = result needs model to learn

Study Hours
AWS Experience
IT Experience
↓
Features

Exam Score
↓
Label

The model learns the relationship between features and labels to predict new data.

3. Train / Tune / Deploy

  • Train = model learned from historical data
  • Tune = try configurations to get a better model
  • Deploy = send the model to the endpoint for the application to call
Train
↓
Tune
↓
Model Artifact
↓
Deploy Endpoint
↓
Application
↓
Prediction

4. Managed but still have to check the model

SageMaker manages the infrastructure, but the model still depends on:

Training Data · Feature · Label · Model Quality

If data is wrong:

Bad Data
↓
Bad Model
↓
Bad Prediction

Also need monitor: Model Quality · Data Drift · Prediction Quality

5. Use Cases

Use cases:

Customer History
↓
SageMaker
↓
Churn Prediction
Transaction Data
↓
SageMaker
↓
Fraud Risk Score
Sales History
↓
SageMaker
↓
Demand Forecast

6. SageMaker Batch Transform vs Real-Time Endpoint

Inference modeMechanisms & Use Cases
SageMaker Batch TransformRun offline batch inference on large data sets stored in S3 and then write the results to S3, automatically turn off compute when the job is finished — used when immediate results are not needed for each request (not used for ETL data cleaning)
SageMaker Real-Time EndpointMaintain a continuously running HTTPS endpoint to deliver predictable low latency (milliseconds) for each online request
Quick review · SAA-C03

SageMaker AI is a machine learning lifecycle management platform from data preparation/training to deployment.

Amazon Kendra & Amazon Personalize

Purpose: Amazon Kendra is used to search and find answers in documents, while Amazon Personalize is used to suggest suitable content/products for each user.

Kendra = Intelligent Document Search

Personalize = Recommendation Engine

1. Amazon Kendra

Kendra uses ML to search the knowledge base using natural language.

Documents
↓
Kendra Index
↓
User Question
↓
Relevant Answer / Result

Data sources can be: S3 · RDS · Google Drive · SharePoint · OneDrive · Salesforce · ServiceNow · PDF / Word / HTML / FAQ

For example:

"Where is the IT support desk?"
↓
Kendra
↓
Find the answer in internal documentation

Kendra = smart search on documents, not just simple keyword matching.

2. Amazon Personalize

Personalize uses user behavior to create recommendations.

User / Item / Interaction Data
↓
Personalize
↓
Recommendation
User buys Gardening Tools
↓
Personalize
↓
suggestion:
Seeds
Gloves
Watering Can

Can be used for: Website · Mobile App · Email · SMS

In addition to recommending items, Personalize can also:

Re-rank list = reorder the list according to each user

3. Kendra vs Personalize

Kendra = "What information is the user looking for?"

Personalize = "What item should this user see next?"

Documents
↓
Kendra
↓
Search / Answer
User Behavior
↓
Personalize
↓
Recommendation
