Amazon CloudWatch: metrics, logs, alarms & insights

Purpose: Amazon CloudWatch is used to monitor the AWS system with metrics, logs, dashboards and alarms.

CloudWatch = Metrics + Logs + Dashboard + Alarms

It replied: "How is the system running?"

Other than: CloudTrail = who called which AWS API?

1. Functional groups and EventBridge

Functional groupWhat to use?
MetricsCollect measurements over time: CPU, latency, request count
LogsCentralize application/service logs
DashboardsDisplays graphs and system status
AlarmsMonitor conditions/status for alerts or action calls
InsightsAnalyze logs and observe specialized workloads such as containers/Lambda
CloudWatch Events → Amazon EventBridgeReceive events, use filtering rules and pass to targets like Lambda/SQS

These are functional groups, not mutually exclusive types of monitoring. CloudWatch Events is the former name of Amazon EventBridge; Alarm tracks metrics, EventBridge routes events such as EC2 state changes or state change alarms.

Amazon EventBridge

Purpose: Amazon EventBridge is a serverless event bus used to receive events, filter events, and automatically send events to other services.

EventBridge = receive event + filter event + route event to target

"Something happened"
↓
EventBridge detected
↓
"Then do something"

1. Basic Flow

Event Source
↓
EventBridge Bus
↓
Rule
↓
Target

For example:

EC2 is stopped
↓
EventBridge
↓
Rule match
↓
Lambda / SNS / SQS

Rule decides when to run, Target is the service that actually works.

2. Event Source

EventBridge can receive events from: AWS Services · SaaS Applications · Custom Applications · CloudTrail

EC2 state change · S3 event · CodeBuild failed · CloudTrail API call · Custom application event

3. Rule

Rules have 2 main types:

3.1. Event Pattern

Runs when an event meets the conditions.

Event occurs
↓
Rule checks JSON
↓
Match?
↓
Target
EC2 State = stopped
↓
EventBridge Rule
↓
SNS Alert

3.2. Schedule / Cron

Run over time.

Every 1 hour
↓
EventBridge
↓
Lambda
00:00 every day
↓
EventBridge
↓
Lambda cleanup temporary files

4. Target

Target is the service that handles events after the rule match.

Could be: Lambda · SQS · SNS · Step Functions · ECS · AWS Batch · Kinesis · CodePipeline · CodeBuild · SSM

Order Created
↓
EventBridge
↓
SQS
↓
Order Worker

5. Event Bus

  • EventBridge has the following bus types: Default Event Bus = AWS service events
  • Partner Event Bus = SaaS like Datadog/Zendesk
  • Custom Event Bus = event from your application

↓

↓

6. Producer & Consumer separate

EventBridge key points:

Producer
↓
EventBridge
↓
Consumer

The producer does not need to know who handles the event.

↓
"OrderCreated"
↓

├── Inventory Lambda
├── Email SQS

Order Service only broadcasts events, no need to call each service directly.

7. CloudTrail + EventBridge

CloudTrail records AWS API activity.

↓

↓

Event example:

  "orderId": "123",

Which IP?
What time?

1. CloudTrail vs CloudWatch

CloudTrail = who did what on AWS?

CloudWatch = How is the system working?

EC2 is deleted
→ CloudTrail

EC2 CPU = 95%
→ CloudWatch

CloudTrail records activity from: AWS Console · CLI · SDK · AWS Services · IAM User / Role

CreateSubnet · DeleteBucket · TerminateInstances · AttachRolePolicy

5. Types of Events

5.1. Management Events

Is an AWS resource management operation.

CreateSubnet · AttachRolePolicy · CreateTrail · TerminateInstances

Can be divided: Read = read only

Write = change resources

Management events are the most common type when investigating who edited/deleted a resource.

6. Data Events

Is an activity directly on data/object/function.

S3 GetObject · S3 PutObject · S3 DeleteObject · Lambda Invoke

Data events: High volume · Higher cost · No default logging

So it's usually only enabled for important resources.

AWS Config & compliance automation

Purpose: AWS Config is used to monitor the configuration of AWS resources over time and check whether the resource complies with the rules or not.

AWS Config = Configuration History + Compliance Check

It replied: How are resources configured? · What was the previous configuration like? · Is it compliant with the rule?

1. Easy to understand example

You have rule: Security Group · do not open SSH 22 for 0.0.0.0/0

If there is SG: Port 22 · Source = 0.0.0.0/0

Config rating: NON_COMPLIANT ❌

If only for corporate IP: Port 22 · Source = Company IP

→

COMPLIANT ✅

Config = check if the configuration has the correct policy.

2. What does AWS Config track?

For example:

Security Group · S3 Bucket · EC2 · EBS · ALB · IAM · ...

May know: Current configuration · Previous configuration · When the configuration changed · Compliance status

3. Resource Timeline

Config saves the resource's change history.

10:00 · S3 Bucket = Private · 11:00 · S3 Bucket = Public · 12:00 · S3 Bucket = Private

Config Timeline helps view: When do resources change · Configuration before/after · How compliance changes

Can link to CloudTrail to see which API call caused the change.

4. Config Rules

Rule is used to check configuration.

S3 Buckets
→ cannot be Public

Security Group
→ Do not open SSH all over the Internet

ALB
→ must have SSL Certificate

There are 2 types: AWS Managed Rule = Ready-made AWS

Custom Rule = your own logic = usually use Lambda

According to Schedule
↓
Config checked periodically

Config detects after configuration occurs, not firewall to block previous action.
