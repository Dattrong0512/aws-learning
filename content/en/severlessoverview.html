19. Lambda Layers, SnapStart, Runtime, Memory–CPU Ratio & Hyperplane ENI

Lambda featureThe core point needs to be distinguished
Lambda LayersReuse common libraries/code between multiple functions; each Layer version is immutable — publishing a new version does not automatically change the function pointing to the old version (large data hundreds of MB–GB read/write at runtime, use EFS)
Lambda SnapStartTake a snapshot of the initialized environment to drastically reduce cold starts; only works on published versions (not applicable to $LATEST)
Runtime & Container ImageSupports any language via Custom Runtime and Linux container images up to 10 GB (Windows containers not supported)

Purpose: Amazon DynamoDB is a serverless NoSQL database with low latency, self-scaling and no need for server management.

AWS Step Functions

Purpose: Coordinate multiple processing steps with clear status, retry, and error handling.

1. State machine

Workflow includes states such as Task, Choice, Parallel, Map, Wait, Succeed and Fail. Tasks can call Lambda or AWS service integrations, not just connect Lambda to Lambda.

Receive order → validate → inventory/payment → Choice
                                        ├─ success → delivery
                                        └─ error → compensation processing / failure reporting

2. Retry, Catch and side effects

Retry handles temporary errors of a step; Catch switches to the error handling branch. Set timeout to avoid waiting indefinitely.

The retried task can perform the action again, so idempotency should be designed for that
pay/send order.
Workflow does not automatically rollback all changes to external services; Use steps
compensation when needed.

3. Standard and Express

TypeSuitable
StandardWorkflow is long, needs history/audit; Maximum one year, job/callback support according to integration
ExpressHigh event rate, short tasks; Maximum 5 minutes, mainly request-response

Standard uses exactly-once workflow execution according to the service model, but Retry can still call the task again.

Asynchronous Express
= at-least-once; Synchronous Express is at-most-once.

Don't understand execution guarantees as side effect guarantees that never overlap. AWS workflow types.

4. Human approval

Standard workflow can wait for callback/task token for approval or external job.

The system sends success/failure results in tokens with appropriate permissions; set timeout and branch when there is no response.

The state machine role needs permission to call services; The task's network/permission must still be correct.

5. Use cases

Use cases: Order fulfillment with multiple steps, data processing with parallel/Map, workflow requires human approval. A simple short task that doesn't require additional Step Functions; A multi-state/retry sequence is appropriate.

Quick review · SAA-C03

Step Functions coordinates multi-step workflows, handling state/retry/error; Lambda executes code, not replacing the entire orchestration workflow.

AWS AppSync

Purpose: Build a completely serverless GraphQL API and real-time update channel (Pub/Sub WebSockets), combining multiple data sources in a single query.

1. Core characteristics

AWS AppSync: managed GraphQL & Pub/Sub API services allow clients to retrieve only the necessary data fields from DynamoDB, Aurora/RDS, OpenSearch, Lambda or HTTP APIs through a single endpoint.

2. Compare AWS AppSync vs Amazon API Gateway

CriteriaAWS AppSyncAmazon API Gateway
Primary communication modelGraphQL & Real-time Pub/Sub Subscriptions (Pre-managed WebSockets)REST API, HTTP API and the general WebSocket API
Merge multi-source dataResolvers collect data from multiple tables/services in one request, avoiding over-fetchingOften a composite Lambda/backend layer is needed or the client has to call multiple REST endpoints
Authentication supportAPI Key, IAM, Cognito User Pools, OIDC and Lambda AuthorizerIAM, Cognito User Pools, Lambda Authorizer, Mutual TLS
