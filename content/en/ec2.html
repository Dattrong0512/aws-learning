Amazon EC2 fundamentals & launch configuration

Purpose: Run virtual servers when you need to control the operating system, software and how applications work.

1. What is EC2?

EC2 rents compute on demand. AWS manages the physical infrastructure; You manage the OS, patches, software and application data on your device.

An instance resides in an AZ. If you want to tolerate AZ errors, you need many instances across many AZs; A large machine does not automatically create High Availability.

2. Options when creating a machine

Key pairUsed when logging in SSH; Can be administered using Systems Manager if configured properly

3. User Data

User Data is usually a script that installs a package, loads configuration, or starts an application.
On Linux, by default the script runs as root on first boot; can structure
image reruns.

Do not put secrets directly in User Data. When needed, the application retrieves secrets from the Secrets Manager/Parameter Store using a role with limited permissions.

4. Compile into a scalable application

Users → ALB → EC2 in Auto Scaling Group in multiple AZs
                   └─ Persistent data in appropriate database/storage

Launch Template saves instance creation configuration so ASG can recreate machines consistently. CloudWatch monitors load; ASG adjusts engine numbers.

5. CloudWatch monitoring

EC2 monitoring modeCollection Cycle & Range
Basic MonitoringDefault free: most EC2 metrics sent each 5 minutes (Status check metrics are still available every 1 minute)
Detailed MonitoringPay extra to receive EC2 host metrics every time 1 minute; no automatically collect RAM or disk inside the OS (AWS Docs)
CloudWatch AgentInstall inside the OS to push RAM, swap, disk space and application logs to CloudWatch

6. Use cases

Use cases: Web/API needs its own package; Legacy applications need OS control; batch or HPC needs specific type of CPU/GPU. Use tags to manage and view costs by environment.

EC2 instance types, lifecycle & Hibernate

Purpose: Choose the machine configuration and shutdown method appropriate to resources, startup time and data to keep.

1. Select instance family

FamilySuitable
T/M – general purposeWeb, dev/test; T instances use CPU credits for burst workloads
C – compute optimizedHeavy processing of CPU, encoding, batch
R/X – memory optimizedIn-memory database, large dataset in RAM
I/D – storage optimizedLocal I/O or large data on disk
P/G – accelerated computingGPU, ML or graphics

The name m5.2xlarge includes family M, generation 5 and size 2xlarge.

No need to memorize the vCPU table of each machine; Select by CPU, RAM, I/O or network bottleneck.

2. Reboot, Stop and Terminate

OperationWhat happens?
RebootRestart the OS; holds instance and storage.
StopStop EBS-backed instance: keep EBS, lose RAM and Instance Store. Self-provisioned Public IPv4 usually changes when restarting.
TerminateDelete instance. EBS with DeleteOnTermination will be deleted; Volumes that do not enable this attribute remain and continue to charge.

Note: Stop does not free EBS.

3. Hibernate

Hibernate writes RAM to the encrypted EBS root volume and then stops the computer.

When starting, RAM and processes are reloaded, which means the application takes a long time to prepare data in memory.

RAM → EBS root encrypted → stop → start → reload RAM

Must enable hibernation support when launching, use a supported device/AMI, and root with enough RAM space.

Do not keep hibernate for more than 60 days; Instance Store still loses data. Details limited by OS.

4. Use cases

Use cases: C-family for video encoding; R-family for data processing in RAM. Hibernate for dev environments or slow application startups; Use Multi-AZ and backup to protect availability/data.

Quick review · SAA-C03

Reboot keeps the instance; Stop keeps EBS but loses RAM; Terminate deletes the instance according to disk configuration. Hibernate saves RAM to encrypted EBS to restore state.

EC2 networking, Security Groups & IAM

Purpose: Control your application's network connectivity and access to AWS on EC2.

1. Security Group

Security Group is a stateful firewall attached to ENI.
There is only Allow rule; The rules of multiple SGs are combined.
The new SG defaults to no inbound and no outbound; The response of the connection is
self-passage.
Internet → ALB SG: HTTPS 443
ALB → App SG: indicates the source is ALB SG
App → DB SG: indicates the source is App SG on the database port

SG reference helps avoid having to update IP when ASG changes machines.

Timeout can be due to SG, NACL or route; connection refused is usually because there is no listening service on that port.

2. Public and private IP

Private IP used in VPC network.

EC2 direct Internet access needs public IP with route to Internet Gateway and appropriate network rules; Just being in the public subnet is not enough.

Private instances can go to the Internet via NAT or call AWS services via VPC
Endpoint.
Commonly used SSH 22, HTTPS 443, RDP 3389; Should limit administrative sources or use
Systems Manager.

3. ENI and Elastic IP

ENI: Virtual network card contains private IP, MAC and SG, belonging to one AZ.

Secondary ENI can switch between instances in the same AZ; primary ENI is not removed from the instance in use.

Elastic IP is a fixed public IPv4 that can be reattached to another resource.
Public IPv4 has a fee; Prioritize ALB/DNS if fixed IP is not needed.
The default EIP Quota is usually 5 per Region, can be increased.

4. Enhanced Networking and EFA

Elastic Fabric Adapter (EFA) is a network interface for EC2 running HPC or distributed ML, helping instances exchange data with low latency and high throughput.

MechanismFunction
Enhanced Networking / ENASR-IOV helps increase bandwidth/PPS and reduce latency for conventional IP networks. ENA is the modern choice; Intel 82599 VF is legacy.
EFAAdd OS-bypass via Libfabric for MPI/NCCL compatible applications; tightly coupled workloads require continuous data exchange.

Needs instance type, OS, driver/library and Security Group supported by EFA. Used for multi-node HPC simulation or distributed ML training.

5. IAM role for EC2

Instance profile brings the IAM role into EC2.
SDK retrieves temporary credentials via metadata service; Enable IMDSv2 and grant dark permissions
minimal.
Do not save personal access keys on the device.

Network permission and IAM permission are two separate layers: opening a port does not grant read access to S3; Role level does not create network routes.

6. Use cases

Use cases: EC2 private reads S3 by role and S3 VPC Endpoint. ALB receives HTTPS from users, EC2 only receives requests from ALB SG, database only receives requests from app SG.

7. Detailed distinction between ENA vs EFA (Networking & HPC)

CriteriaENA (Elastic Network Adapter)EFA (Elastic Fabric Adapter)
Main purposeEnhanced Networking standard for EC2 (high bandwidth, large PPS)HPC & Distributed AI/ML multi-node tightly coupled
Transmission mechanismGoes through the operating system's TCP/IP stackSupport OS-bypass qua Libfabric and communication MPI to minimize latency
Quick review · SAA-C03

Security Group is the stateful firewall for ENI; IAM Role grants AWS API permissions, not routes or network rules. Fast exchange multi-node HPC → consider EFA.

EC2 purchasing & placement strategies

Purpose: Reduce costs and choose the right machine placement for latency, fault tolerance or licensing requirements.

Choose to buy by workload:

On-Demand = flexible
Savings Plans / Reserved Instances = commitment to discounts
Spot = low prices, subject to disruption
Capacity Reservation = capacity reservation

1. Choose how to pay

ChooseWhen used
On-DemandUnpredictable loading, short-term, unwilling to commit
Reserved InstancesStable loading, 1 or 3 year commitment; Standard/Convertible have different levels of flexibility
Savings PlansCommit to spending per hour for 1 or 3 years
SpotLoad is tolerant of interruptions, has retry/checkpoint
Capacity ReservationNeed to keep capacity at one AZ, no discount
Dedicated InstanceNeed hardware isolated from other accounts
Dedicated HostNeed to control physical host or license by socket/core

Compute Savings Plans are flexible across family/Region and Fargate/Lambda; EC2 Instance Savings Plans are tied to family and Region, flexible in size/OS/tenancy.

Regional RI and Zonal RI

Scope of RIDiscountKeep capacity
Regional RIApplicable in Region; Has size flexibility for Linux/UNIX, default tenancy when appropriateNo
Zonal RIApplies to matching EC2 configurations in the selected AZ; no AZ/instance-size flexibilityYes, for specific configurations within an AZ

Standard/Convertible is the offering class; Regional/Zonal is scope, two different classifications.

2. Spot needs an interruption-tolerant design

Spot uses available capacity and can be reclaimed by AWS.

Interruption announcements are usually made about 2 minutes in advance; do not consider it a guaranteed time for any interruption.

Use multiple instance types/AZ, checkpoints and external persistent data storage
instance. instance.
Consistent batch, CI and worker reruns; poor job fit impossible
interruption.

3. Keeping capacity is different from discounting

Capacity Reservation guarantees capacity in the selected AZ; still pay for the portion kept even if not used.

Matching discounts from RI/Savings Plans may be combined; Regional RI/Savings Plans do not hold their own capacity; Zonal RI holds capacity for matching configurations in the selected AZ.

4. Placement Groups

StrategyHow to set up the machineTrade-off
ClusterClose together in an AZLow Latency, high throughput; does not accept AZ's fault
SpreadSeparate hardware for each machine, possibly multiple AZsIsolate small groups of important machines; Up to 7 running instances/AZ with rack-level spread
PartitionSplit a rack group into partitionsKafka/HDFS/Cassandra fusion; Maximum 7 partitions/AZ

5. Use cases

Use cases: HPC needs very fast exchange nodes: Cluster. Important nodes that need to be isolated for hardware errors: Spread. Large distributed system self-replicates data: Partition. Batch can be run again: Spot combined with checkpoint.

6. Distinguish between Regional RI vs Zonal RI & Offering Class

RI Properties (1 or 3 years)Core distinction
Regional RI vs Zonal RIRegional RI flexible AZ and instance size in the same family but does not hold capacity; Zonal RI attaches a specific AZ and There is a capacity reservation

Quick review · SAA-C03

Spot is economical but can be disruptive; Savings Plans/Regional RI reduces prices but does not maintain capacity. Cluster/Spread/Partition are three different ways of distributing instances.

EC2 Storage Options

Purpose: Select persistent disk, temporary disk or shared file for EC2.

1. Compare storage

StorageMain characteristics
EBSBlock storage over the network, in the same AZ as EC2. Keep data when stopped; terminate delete or keep depending on DeleteOnTermination, the default root is usually deleted.
Instance StoreDisk local, fast I/O. Data loss when stopping/hibernate/terminate or host failure; reboot still holds. Contains only reproducible data.
EFSManaged NFS/POSIX for Linux, multiple EC2 mounts. Regional EFS is shared across many AZs, capacity expands automatically.

2. EBS volume types

TypeSuitable
gp3 / gp2 — SSDGeneral purpose. gp3: baseline 3,000 IOPS, 125 MiB/s; IOPS/throughput are capacity independent. gp2: IOPS increases with size, has burst credits.
io1 / io2 Block Express — SSDDatabase needs high IOPS, stability and low latency.
st1 — HDDBig data, warehouse, log; throughput for regular sequential I/O.
sc1 — HDDLow-access data, low cost priority.

Boot volume used SSD. EBS charges for provisioned capacity, even when EC2 is stopped.

EBS featureConditions & Notes
Multi-AttachSupport only io1/io2, maximum 16 EC2 Nitro in same AZ; Required to use application and cluster-aware file system (not using regular EXT4/XFS for multiple machines to record at the same time)
EncryptionKMS protects volumes, EC2–EBS traffic and snapshots; Do not enable it directly on the old unencrypted volume, but must create a new volume from the snapshot

3. Snapshots and AMIs

Snapshot = backup EBS at a time, save the changed block next time
Convert AZ = snapshot → create volume at destination AZ → attach EC2
AMI = OS/software/configuration model to launch EC2; belongs to Region, can be copied

Snapshots do not need detach, but need flush/pause writes for consistency. Archive: restore 24–72 hours; Recycle Bin: keeps snapshots deleted by mistake for 1 day–1 year; FSR: avoids slowness when reading the block for the first time, has separate fees.

4. EFS

EC2 Linux → mount target in AZ → shared EFS. The SG of the mount target is open TCP 2049 from SG EC2; Encrypt at rest with KMS, in transit with TLS.

Regional = multiple AZs; One Zone = one AZ, lower cost
General Purpose = low latency
Elastic = self-adjusting throughput; Provisioned = reserved
Bursting = throughput according to Standard capacity and credits
Standard = regular access; IA/Archive = less traffic
Lifecycle policies = automatically change class according to inactive time

IA/Archive has an access fee; Archive requires Regional + Elastic throughput. One Zone supports Standard/IA.

5. Use cases

Use cases: EBS gp3 for boot/app; io2 for databases; Instance Store for cache/scratch; Regional EFS for shared WordPress upload directory between multiple EC2s.

Details: trang EBS.

Quick review · SAA-C03

EBS = persistent block disk in an AZ; EFS = shared file system; Instance Store = temporary local disk. Choose according to durability and sharing needs.
